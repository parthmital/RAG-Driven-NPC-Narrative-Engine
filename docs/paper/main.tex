\begin{abstract}
Large language models let non-player characters converse, yet they forget early facts, propose changes that break game rules, and grow costlier as context lengthens. This paper presents \Sys{}, a dialogue engine that separates generation from state control. A dual-tier memory scopes retrieval to the current location and character, and every proposed change to the event-sourced state must pass a symbolic validation barrier before commit. The engine is compared at an equal prompt budget with six memory baselines, including the Generative Agents retrieval rule, in a memory-by-control factorial with eight ablations on seven worlds and four models, and an independent invariant oracle audits every committed change. With a 7-billion-parameter backbone, the engine recalled 63.7\% of facts at least 20 turns old on held-out worlds, against 0.0\% for a rolling context and 54.2\% for the Generative Agents rule, while flat vector memory reached 69.3\%. Through the barrier, no audited invariant was violated in probes or live play, and none of 26{,}273 random unlawful proposals was accepted, against 4.4\% attack success under direct writes. An offline canonicaliser removed the rejections of lawful requests that named entities by display name (20.0\%), and recovery was exact after 300 simulated crashes.
\end{abstract}

\section{Introduction}\label{sec:intro}

\IEEEPARstart{I}{n} text-centric games, players move, handle objects and talk to characters through language, so the world remains coherent only if an explicit symbolic state backs it. Dialogue trees and finite-state machines respect the rules cheaply but confine players to authored choices. Large language models (LLMs) lift that limit, but a survey of LLMs in games names hallucination, weak grounding and loss of continuity among their main open problems, including non-player characters (NPCs) that invent quests the game does not contain \cite{gallotta2024llmgames}.

Three failure modes stand in the way. First, \emph{long-horizon forgetting}: facts outside a bounded context are lost, facts inside a long context are used unevenly \cite{liu2024lost}, and very long-term conversational memory remains weak even with retrieval \cite{maharana2024locomo,wu2025longmemeval}. Second, \emph{invariant violations}: LLMs are unreliable simulators of state transitions \cite{wang2024worldsim,kim2023entity} and lose narrative commitments \cite{ma2026ncp}, so unchecked they move players between unconnected rooms, invent items and grant unearned money. Third, \emph{cost growth}: full history, or several reflective LLM calls per turn \cite{park2023generative,shinn2023reflexion}, raises tokens and latency.

This paper evaluates an engine that separates generation from state control and compares it with the base paper, Generative Agents \cite{park2023generative}. The engine's parts, namely a turn buffer, dense retrieval, schema-constrained output, a rule validator, an append-only event log and a deterministic reducer, are each established techniques. The contribution therefore lies in an evaluation that isolates what each mechanism provides against independent baselines and measures its costs. Five research questions guide it. \textbf{RQ1}: does scoped dual-tier memory improve long-range recall per prompt token over rolling-context, vector-memory and generic retrieval agents? \textbf{RQ2}: does a pre-commit validation barrier over event-sourced state reduce committed invariant violations, and at what cost in false rejections and dialogue--state desynchronisation? \textbf{RQ3}: do memory and control contribute independently? \textbf{RQ4}: what latency and tokens does each component add? \textbf{RQ5}: do the effects hold across worlds of different authorship, genre and scale, and across backbones? The contributions are:
\begin{enumerate}[leftmargin=*]
  \item a formal account of the engine as implemented, including the post-filter limit of its scoped retrieval (\cref{sec:formal}),
  \item a \emph{paired five-way commit protocol}: each LLM output is committed through the corrected barrier, a canonicalising variant, the earlier barrier, the reducer alone and by direct writes, and audited by an eight-invariant oracle that imports nothing from the validator, with a lawful \emph{twin} for every attack and a differential test on random proposals (\cref{sec:protocol}),
  \item a seven-world benchmark from four families and a single-notebook harness that reports recall, retrieval quality, violations, false rejection, desynchronisation, latency, tokens and replay consistency with pre-registered hypotheses (\cref{sec:setup}),
  \item measured effects and costs from the final run of a protocol revised after auditing four earlier runs, with a paired before-and-after test of the corrections, the false-rejection cost of grounding, a failure-mode analysis and a verdict on every pre-registered hypothesis (\cref{sec:results,sec:discussion}).
\end{enumerate}
The supplementary material, numbered with an S prefix, holds the algorithms, dataset, run audit and secondary results.

\section{Literature Survey}\label{sec:related}

\emph{Grounded dialogue and text games.} LIGHT conditions dialogue on rooms, objects and personas in a crowd-written fantasy world \cite{urbanek2019light}, and goal-driven LIGHT agents were trained with reinforcement learning \cite{ammanabrolu2021dragon}, but neither keeps a validated world state over long sessions. TextWorld \cite{cote2019textworld} and Jericho \cite{hausknecht2020jericho} enforce rules but parse a constrained command language with no open NPC dialogue. Callison-Burch et al.~\cite{callisonburch2022dnd} cast Dungeons and Dragons play as a dialogue task that includes predicting game state, and STORIUM anchors collaborative stories with structured cards \cite{akoury2020storium}.

\subsection{Base paper: Generative Agents}\label{sec:base}
Generative Agents \cite{park2023generative} is the most direct prior architecture for LLM-driven characters with long-term memory in a game-like world. Twenty-five agents in a sandbox town keep a \emph{memory stream} of natural-language observations. Retrieval scores each memory as the equally weighted sum of min-max-normalised recency (decay 0.995 per sandbox hour), importance (an integer from 1 to 10 that the LLM assigns on creation) and relevance (cosine similarity), and reflections are synthesised when summed importance exceeds 150. Its evaluation ranks believability: 100 human evaluators ranked interview answers of the full architecture and its ablations. Its memory is not bound to a validated symbolic state, and the paper reports embellished memories. Every memory write costs an LLM call, and two simulated days of 25 agents cost thousands of dollars in token credits. Recall of established facts and rule violations are not measured.

\emph{Memory for LLM agents.} Reflexion stores verbal self-reflections \cite{shinn2023reflexion}, and summarising earlier sessions helps multi-session chat \cite{xu2022goldfish}. Later systems add forgetting curves \cite{zhong2024memorybank}, knowledge-graph indexing \cite{gutierrez2024hipporag}, linked notes \cite{xu2025amem}, multi-granularity summaries with retrieval refined by reinforcement learning \cite{tan2025rmm} and compressed memory units \cite{liu2026simplemem}. Benchmarks show that long-term memory is far from solved \cite{maharana2024locomo,wu2025longmemeval}, and surveys organise the design space \cite{sumers2024coala,zhang2025memorysurvey}. None binds memory to a validated symbolic state or compares designs at a matched token budget in a game. Established systems enter the comparison through their retrieval rules at the shared budget (Generative Agents as B4, MemoryBank as B5, \cref{sec:conditions}), because A-Mem and HippoRAG build their indices with LLM calls at write time (note construction and linking, open information extraction), a cost the equal-budget comparison would not count.

\emph{Retrieval and long context.} Retrieval-augmented generation (RAG) grounds an LLM's output in passages fetched from a dense index \cite{lewis2020rag}, ranking them by similarity alone, without regard to a turn's spatial or social scope. Longer contexts are no substitute, since models use their middle poorly \cite{liu2024lost}, and ReAct keeps a growing scratchpad \cite{yao2023react}. Scoping is a filtered nearest-neighbour query, and post-filtering a global top-$k$ loses in-scope neighbours, which motivates filter-aware indices \cite{gollapudi2023filtered} (\cref{prop:postfilter}).

\emph{State tracking and verifier-gated generation.} LLMs track entities imperfectly \cite{kim2023entity} and simulate text worlds unreliably \cite{wang2024worldsim}. LLM-Modulo argues for external model-based verifiers of LLM proposals \cite{kambhampati2024llmmodulo}, grammar-constrained decoding guarantees syntax but not legality \cite{geng2023gcd}, and indirect prompt injection shows that text inside a model's input can override its instructions \cite{greshake2023indirect}. Event sourcing derives state from an append-only log in industrial systems that need an auditable history \cite{overeem2021eventsourcing}.

\emph{LLM NPCs and narrative games.} PANGeA lets the LLM itself judge player input against design rules \cite{buongiorno2024pangea}, and Phillips et al.\ advance goal-based conversation states with an LLM that reads the dialogue history \cite{phillips2025goal}. SceneCraft generates branching NPC scenes \cite{kumaran2023scenecraft}, and CALYPSO supports Dungeon Masters with grounded LLM text \cite{zhu2023calypso}. In NCP-Bench, the strongest model preserved its narrative commitments in 42\% of runs over 20 turns, and models contradicted established facts at rates between 40\% and 68\%, as scored by LLM auditors \cite{ma2026ncp}. \Cref{tab:related} contrasts these systems as their own evaluations describe them. An independent audit there means that violations are scored by a checker that shares no code with the evaluated component.

\section{Research Gap}\label{sec:gap}

The survey leaves six gaps. \textbf{RG1:} memory is not bound to validated state (\cref{tab:related}). \textbf{RG2:} in-game state changes are judged by a model \cite{buongiorno2024pangea,phillips2025goal} or not at all, so symbolic pre-commit validation of LLM-proposed mutations is unevaluated in NPC dialogue. \textbf{RG3:} violations are scored by the component under test or by LLM auditors that can err on ambiguous text \cite{ma2026ncp}, never by a rule checker sharing no code with the validator on identical outputs. \textbf{RG4:} memory designs are rarely compared at an equal prompt-token budget, and the base paper reports cost only as token credits. \textbf{RG5:} false rejection, dialogue that contradicts rejected changes, and crash recovery are not reported with recall and violations. \textbf{RG6:} memory and state control are studied apart, so whether combining them keeps both benefits or lets one degrade the other is unmeasured. RQ1 to RQ5 address these gaps, RQ3 through a factorial that tests RG6 directly.

\section{Proposed Methodology}\label{sec:method}

\subsection{Formal model}\label{sec:formal}
The model is the one the code implements. Module paths refer to \repolink{\repo/tree/\evalcommit/Backend}{\code{Backend/}} at the evaluated commit. The engine also exists in an earlier version, frozen at the second project review and called Review-02 below. Its corrections are tested in \cref{sec:before-after}.

\begin{definition}[World state]\label{def:state}
A world state is a tuple $S=(\mathcal{L},A,\mathcal{N},\mathcal{O},\pi,\iota,c,R,J,t)$ where $\mathcal{L}$ is the set of locations with directed adjacency $A\subseteq\mathcal{L}\times\mathcal{L}$, $\mathcal{N}$ the NPCs (location, persona, knowledge, conditional secrets, \code{alive} flag), and $\mathcal{O}$ the objects (location in $\mathcal{L}\cup\{\bot\}$, owner). The player's location is $\pi\in\mathcal{L}$, the inventory $\iota$ and the currency $c\in\mathbb{Z}_{\ge 0}$. The trust map is $R:\mathcal{N}\times(\mathcal{N}\cup\{\text{player}\})\to[-100,100]$, the journal $J$ and the turn $t$ (\bsrc{schemas/world_state.py}).
\end{definition}
The seed $S_0$ fixes the canonical entity sets $\mathcal{L}_0,\mathcal{N}_0,\mathcal{O}_0$, and the active NPC and player identity are restored from events, so the whole stored state is derived from the log.

\subsubsection{Events, reduction and replay}
An event $e=(\mathit{id},t,\tau,p,\mathit{ts})$ has one of 14 types $\tau$ (\bsrc{schemas/events.py}). The reducer $\delta$ (\bsrc{core/reducer.py}) deep-copies the state and applies one event, ignoring moves to unknown locations, clamping trust to $[-100,100]$ and flooring currency at zero, so
\begin{equation}\label{eq:fold}
S_{T}=\foldl(\delta,S_0,[e_1,\dots,e_T]),\qquad S_{i}=\delta(S_{i-1},e_i).
\end{equation}
Events are appended to SQLite in one transaction per turn, and every $\Delta=16$ turns a snapshot $(S_k,\mathit{id}_k)$ is written atomically.

\begin{proposition}[Replay and snapshot equivalence]\label{prop:replay}
If (i) $\delta$ depends only on $(S,e)$ and (ii) every change to the hashed state is a logged event applied by $\delta$, then for a snapshot after event $k$, $\foldl(\delta,S_0,e_{1..T})=\foldl(\delta,S_k,e_{k+1..T})$.
\end{proposition}
\begin{proof}
A left fold over a concatenated list folds the suffix from the prefix's result, which is $S_k$. Condition (i) holds because the reducer's only time-dependent value, a journal timestamp, is read from the persisted event. Condition (ii) failed in the Review-02 version for the active NPC, which is now an event field.
\end{proof}
Recovery from the latest snapshot costs $O(|S|+r)$ for the $r$ events after it. The corrected load path (\code{recover\_state}, \bsrc{core/recovery.py}) returns $\foldl(\delta,S_k,e_{k+1..T})$, while the Review-02 path returned $S_k$ and discarded every later event.

\subsubsection{Proposals and the validation barrier}
Each turn the LLM returns one JSON object validated by a Pydantic schema: dialogue, narration, a one-sentence memory summary and a list of proposals $P_t=[(\tau_j,p_j)]$. The barrier (\bsrc{game/validator.py}) checks them \emph{in order against a running state} $\hat S_0=S_t$, $\hat S_j=\delta(\hat S_{j-1},e(\tau_j,p_j))$ when accepted, and commits
\begin{equation}\label{eq:commit}
\begin{aligned}
E_t&=[\,e(\tau_j,p_j)\;:\;V(\tau_j,p_j,\hat S_{j-1},S_t)\,],\\
S_{t+1}&=\foldl(\delta,S_t,[e_{\text{speech}}]\mathbin{+\!\!+}E_t).
\end{aligned}
\end{equation}
$V$ requires a canonical, adjacent destination and at most one move per turn, a canonical NPC and a total trust change within $\pm20$ per NPC, a canonical object at the player's location for a take, possession or presence for NPC drops and takes, connected NPC moves, a canonical target for state updates, and integer currency deltas whose total spending stays within the opening balance $c(S_t)$ and whose net gain is at most 50. Engine-only event types and new entities are rejected. After a rejection, a repair node asks the model once to rewrite the reply so that it does not describe the rejected change. The Review-02 barrier, the ``before'' condition, checked each proposal independently against $S_t$, did not bound currency gains and had no repair.

\subsubsection{Invariants audited by the oracle}\label{sec:oracle}
The evaluation's oracle re-derives facts from $(S_{\text{pre}},S_{\text{post}},\text{committed mutations})$ and checks eight invariants written from the specification, not the validator. With $\mathcal{A}$ the undirected closure of the seed adjacency: (O1) the sets of locations, NPCs and objects match the seed, and every reference, trust relationships included, uses a canonical id, (O2) every object occupies a single place, (O3) $\pi_{\text{post}}=\pi_{\text{pre}}$ or $(\pi_{\text{pre}},\pi_{\text{post}})\in\mathcal{A}$, (O4) an object the player newly holds lay at the player's location before, on the floor or carried by an NPC there, and is held only once, (O5) objects move only to the player's location and NPCs only along $\mathcal{A}$, (O6) $|R_{\text{post}}(n,x)-R_{\text{pre}}(n,x)|\le 20$ for every pair, toward the player and between NPCs, (O7) spending $\le c_{\text{pre}}$ and $c_{\text{post}}\ge 0$, and (O8) $c_{\text{post}}-c_{\text{pre}}\le 50$, a bound the Review-02 validator did not implement. The invariants are single-transition properties of places, objects, trust and currency. Location, NPC, flag, journal and clue state is checked only for creating no entity (O1), not for its content, such as an NPC's \code{alive} flag, and dialogue is not read, so secret leaks and contradictions are scored separately (\cref{sec:metrics}).

\subsubsection{Scoped dual-tier memory}\label{sec:memory-formal}
Long-term memory holds entries $m_i=(\mathbf{v}_i,x_i,t_i,\ell_i,n_i)$: the L2-normalised embedding of the player input under all-MiniLM-L12-v2 \cite{reimers2019sbert,wang2020minilm} ($d=384$), the model's memory summary, the turn, the player's location and the active NPC. An exact inner-product FAISS index \cite{johnson2021faiss} returns $\topk_m(\mathbf{q})$, the $m$ most similar entries. With the scope predicate
\begin{equation}\label{eq:scope}
\phi_{\ell,n}(m_i)=\bigl(\ell_i=\varnothing\lor\ell_i=\ell\bigr)\land\bigl(n_i=\varnothing\lor n_i=n\bigr),
\end{equation}
over-fetch $f=5$, threshold $\theta=3$ and $k=6$, retrieval is
\begin{equation}\label{eq:retrieve}
\mathcal{R}(\mathbf{q})=\begin{cases}
\operatorname{first}_k\bigl[m\in\topk_{\min(fk,|M|)}(\mathbf{q}) : \phi_{\ell,n}(m)\bigr]\\
\qquad\text{if this list has}\ \ge\theta\ \text{entries},\\
\topk_k(\mathbf{q})\quad\text{otherwise (fallback)}.
\end{cases}
\end{equation}
The short-term tier is a buffer of the last $B_s=8$ turns, and the store keeps its newest 500 entries when it passes 1{,}000. Memories and buffer share one budget of 1{,}600 characters (\bsrc{llm/prompt_builder.py}): the newest two turns first, then memories in rank order, then older turns, and a memory of a turn already in the history is dropped. The prompt also states the validator's limits from the same constants and shows an NPC's secrets once its trust reaches 60.

\begin{proposition}[Post-filter reachability]\label{prop:postfilter}
An in-scope entry can be returned by the scoped branch of \eqref{eq:retrieve} only if its similarity rank among all entries is at most $fk=30$, so scoped recall falls below exact filtered search when more than $fk-1$ out-of-scope entries are more similar.
\end{proposition}
\begin{proof}
The scoped branch inspects only $\topk_{fk}(\mathbf{q})$.
\end{proof}

\subsection{Turn pipeline}\label{sec:system}
\Cref{fig:arch} shows one turn (\bsrc{graph/definition.py}). The LLM output is treated as untrusted: proposals reach the world state only through the validation barrier (node 6) and the pure reducer inside the commit node (node 8), and node 7 rewrites a reply whose proposal was rejected. The commit node also updates the buffer, the FAISS store and, every 16 turns, the snapshot. On later turns, retrieval (node 2) reads the FAISS store, and prompt assembly (node 3) packs the memories and the turn buffer into one budget.

\emph{Trust boundary.} Two paths change state, and both append an event that the reducer applies. Model proposals must pass the barrier, while player actions from the client (travel, pick-up, drop, clue linking) are checked only by their route handlers and are not audited. Tests at the evaluated commit enforce the layer rules, under which the memory and LLM layers cannot import the barrier or the graph, and pass 3{,}000 randomly generated proposal turns through the barrier without breaking an invariant (\linkpath{\repo/tree/\evalcommit/Backend/}{tests/}).

\subsection{Experimental conditions}\label{sec:conditions}
All conditions share the backbone, decoding, system prompt, state serialisation, output schema and player scripts, and differ only in memory and in how proposals reach state (\cref{tab:conditions}). F1 to F4 form the $2\times2$ factorial, and A1 to A8 each change one component of F4. Baselines are independent NumPy implementations. All memory conditions other than B0, F4v1 and A8 share a limit of 1{,}600 characters, and the rolling contexts receive a token budget $B=401$, the average number of tokens F4 spends on memories and history. Without a validator, schema-valid proposals are written straight into the state (direct writes). B4 re-implements the base paper's retrieval rule, for which the primary model scores each memory's importance a single time, and B5 re-implements the forgetting curve of MemoryBank \cite{zhong2024memorybank}. F4v1 runs the Review-02 validator and prompt on top of the corrected reducer, event store and commit node.

\subsection{Paired five-way commit protocol}\label{sec:protocol}
Each request seed is derived from the probe or turn alone, never from the condition, so the same prompt always yields the same output. A probe prompt contains three history turns, all of which fit within every memory condition, so each probe is asked once, under F4's context. Every parsed output then passes through five commit modes: the corrected barrier, the corrected barrier preceded by a canonicaliser that rewrites display names as ids, the Review-02 barrier, the reducer on its own and direct writes. The oracle audits each result, so any difference between modes stems from the commit path only. Lawfulness is judged by the oracle on a single-proposal transition, both as written and \emph{by intent}, with display names and slugs mapped to ids, so false-rejection and validator-gap rates do not depend on the validator's verdicts (Algorithm~\ref{S-alg:protocol}). A differential test drives the barriers directly with random proposals of every event type in random valid states, labelled by the oracle.

\subsection{Metrics}\label{sec:metrics}
Recall is strict: a probe is correct when the output parses, the reply names the gold key word, and it names neither the distractor's value nor, after a knowledge update, the outdated one. Two secondary analyses use the earlier lenient rule and a re-scoring of hedged replies by a model from a different family. With $r_j$ the rank of probe $j$'s gold memory, $\text{MRR@}k=\frac1n\sum_j\mathds{1}[r_j\le k]\,r_j^{-1}$ and $\text{Recall@}k=\frac1n\sum_j\mathds{1}[r_j\le k]$, computed on probes older than the 8-turn buffer, because packing drops a memory whose turn is buffered. \emph{Attack success} is the share of attacks whose committed changes violate an invariant (a secret leak for secret extraction), \emph{false rejection} the share of lawful twin proposals rejected, and the \emph{validator gap} the share of unlawful proposals accepted. The \emph{violation rate} is 100 times the number of turns whose own committed changes violate an invariant over the committed non-speech mutations, and the share of turns that end in a corrupted state is reported beside it. \emph{Desynchronisation} flags a non-move turn whose dialogue lacks a refusal cue after a rejection, or claims an arrival the state did not commit. Two LLM judges from other families, Qwen2.5-7B-Instruct and Phi-4-mini-instruct, mark replies that claim changes the state did not commit, and a judge's verdicts are used only if it labels at least 80\% of 27 control items correctly. \emph{Replay consistency} compares SHA-256 hashes of the rebuilt and live states, and a \emph{crash trial} stops a commit at a random point and compares the recovered state with the last committed one.

\subsection{Statistical analysis}\label{sec:stats}
Confidence intervals (95\%) come from a percentile cluster bootstrap with 10{,}000 resamples \cite{efron1979,field2007clustered}. Recall and live metrics resample sessions, pooled probe metrics resample attack templates, and a ratio is computed from the resampled numerator and denominator sums. A proportion with no event, or with every row an event, gets an exact Clopper--Pearson interval \cite{clopper1934}. Paired binary outcomes use the exact McNemar test \cite{mcnemar1947} and paired continuous outcomes the Wilcoxon signed-rank test \cite{wilcoxon1945}. The six confirmatory tests of H1 to H3 are Holm-corrected \cite{holm1979}. The factorial is modelled on live turns as a linear probability model
\begin{equation}\label{eq:lpm}
\Pr(y=1)=\beta_0+\beta_M M+\beta_C C+\beta_{MC}MC,
\end{equation}
fitted in statsmodels \cite{seabold2010statsmodels}. Its standard errors are cluster-robust over the 14 live scripts and tested against a $t$ distribution with $G-1=13$ degrees of freedom, the minimum adjustment recommended when clusters are few \cite{cameron2015cluster}. Agreement between judges is Cohen's $\kappa$ \cite{cohen1960kappa}.

\subsection{Hypotheses}\label{sec:hyp}
The hypotheses were fixed before the run. Each is tested against the strongest applicable baseline and counts as supported only when the corrected effect is significant in the predicted direction or its threshold is met. \textbf{H1a}: F4 recall at $a\ge20$ exceeds B1 and B3 at equal or lower token cost. \textbf{H1b}: it is non-inferior to B2 within 5 points. \textbf{H2}: scoping plus fallback gives higher MRR@6 than B2. \textbf{H3}: the barrier reduces committed violations on probes and in live sessions. \textbf{H4}: false rejection by intent is at most 5\% and validation adds under 5\,ms at P95. \textbf{H5}: replay reproduces the live state in every event-sourced session. \textbf{H6}: memory affects recall and control affects violations additively, without significant interaction. \textbf{H7}: the directions of H1 and H3 also hold on each of W2, W3 and W4 and for two further model families. Four tests compare the system with its Review-02 version: \textbf{R1} currency, \textbf{R2} crash recovery, \textbf{R3} contradictions and \textbf{R4} live violations.

\section{Dataset Description and Usage}\label{sec:setup}

The benchmark is generated deterministically by the evaluation notebook from a master seed (\cref{S-sec:dataset-ext}). It has seven worlds in four families (\cref{S-tab:worlds}): W1, the in-house development world of 8 locations, W2a to W2c (16 to 32 locations) converted from the crowd-written LIGHT environment \cite{urbanek2019light} (CC BY-NC 4.0), W3, a 24-location science-fiction station written in the notebook, and the procedural W4-32 and W4-128. No setting was tuned on W2 to W4. \emph{Recall sessions} are teacher-forced scripts of 50, 100 or 200 turns in which facts are planted with an NPC and probed 5 to 160 turns later, each with a paraphrased distractor told to another NPC, so every condition sees the same history. One fact in four is later corrected (a knowledge update), one in two is followed by small talk on the same topic (a lure turn), and no attribute is planted twice in a session. Each condition answers 1{,}045 probes, 897 on held-out worlds, of which 537 have $a\ge20$. \emph{Adversarial probes} cover seven attack categories (teleportation, fabrication, theft, trust inflation, currency, prompt injection \cite{greshake2023indirect} and secret extraction) with six templates each, yielding 1{,}078 attacks paired with 1{,}027 lawful twins. \emph{Live sessions} run the real backend graph for 39 turns with plants, walks, trades, six attacks and four late probes, giving 14 sessions per condition. The data, predictions, metrics and blinded annotation sheets are released with the code.

%=====================================================================
\section{Novelty}\label{sec:novelty}

The components of the engine are not claimed as novel. Relative to the base paper, the engine scopes retrieval by location and NPC without an LLM call per memory write, ties every model-proposed change to a typed, event-sourced state through a symbolic barrier and a pure reducer, and is assessed with automatic, paired, oracle-audited metrics at a matched token budget rather than by believability rankings. No earlier evaluation known to the authors audits symbolic pre-commit validation with an independent oracle on identical model outputs. Three findings follow. (i) Direct writes give 4.4 points of attack success. The reducer's own semantics remove 2.4 of them, the Review-02 validator a further 1.0 and the corrected validator 0.8, and the two secret leaks that remain occur in dialogue, so validator and reducer have to be assessed together. (ii) Because the oracle was written from the specification, it revealed a currency rule that the first validator lacked (a 47.6\% validator gap on currency proposals) and verified the fix on 26{,}273 unlawful random proposals. (iii) The costs of control are quantified, and the largest is grounding: lawful requests that refer to entities by display name rather than id are rejected, and a canonicaliser removes these rejections offline.

\section{Implementation}\label{sec:impl}

The engine has four tiers: a React and TypeScript client over a WebSocket, a FastAPI service with per-session locks running a compiled nine-node LangGraph \code{StateGraph} (\bsrc{graph/definition.py}), the barrier, and storage (the SQLite event log and snapshots, the FAISS store and the buffer). The released game calls a hosted model (\code{openai/gpt-oss-120b} on Groq at temperature 0.35), whereas the evaluation serves its models locally with vLLM \cite{kwon2023vllm}. The benchmark notebook \msrc{notebooks/npc-memory-state-benchmark.ipynb} loads the backend modules of the evaluated commit from a hash-checked bundle, so the only code written for the evaluation is the baselines, the oracle and the data generators. The reported run used two Tesla T4 GPUs on Kaggle for 9.66 hours, \hfmodel{IFM/K2-Horizon-7B} as the primary backbone, and level 5 of twelve pre-declared sample sizes, reached by extending a planned level 3 while time remained (\cref{S-tab:config,S-tab:ladder}). Four earlier runs were audited, and the measurement defects they revealed were corrected before this run (\cref{S-sec:gaps}).

\subsection{Live factorial, ablations and recovery}\label{sec:factorial}
In the live sessions (\cref{S-tab:factorial}), the model itself committed between 2.9\% and 4.9\% of the scripted moves, and the engine carried out the others. With direct writes, 80 of the 103 transitions of F1 and 80 of the 101 of F3 introduced a new violation, chiefly non-canonical entities (O1) and moves between non-adjacent locations (O3). The two conditions behind the corrected barrier had none, and F4v1 committed six currency gains (O8). Live recall reached 46.4\% in F3 and 48.2\% in F4. The planted memory reached the prompt on every live probe, but for 19.6\% of F4's probes the model's own summary of the planting turn had dropped the value (\cref{S-tab:livediag}). The linear probability model (\cref{S-tab:lpm}) separates the factors: memory $\to$ recall $\beta_M=0.464$ ($p=8.6\times10^{-5}$), control $\to$ violation $\beta_C=-0.147$ ($p=2.1\times10^{-7}$), and $\beta_{MC}$ with $p=0.75$ and $1.0$. The two factors combine without loss (RG6): F4 is the only cell that both recalls facts and commits no violation, control shifted recall by $+0.0$ and $+1.8$ points, and memory shifted violations by $-1.9$ and $0.0$ per 100 transitions. Of the ablations (\cref{S-tab:ablations}), only the one without long-term memory (A1) was catastrophic (0.0\%). Dropping the buffer (A2), the fallback (A4), scoping (A3) or the budget (A8) produced no significant loss of recall, while dropping the validator (A5) admitted violations in probes (4.4 per 100 transitions) and in live play (1.9). All event-sourced sessions replayed exactly. Loading a snapshot took 1.1 to 1.5\,ms, against 244.2\,ms for a full replay at turn 160, and the corrected load path was consistent in all 300 crash trials, against 93 for the Review-02 path (\cref{S-tab:replay}).

\section{Discussion}\label{sec:discussion}

\emph{Memory.} With the budget held equal, flat vector memory achieved higher recall than scoped retrieval, and the ranking gain from scoping was small and not significant, on a benchmark that favours scoping because facts are probed with the NPC who heard them. At larger scale, post-filtering can drop in-scope memories (\cref{prop:postfilter}), which filter-aware indices would avoid.

\emph{State control.} The barrier is as strong as its rule set: the oracle exposed a missing currency rule, and once that rule and per-turn checking were in place, no audited violation passed for any model or random proposal. The guarantee is therefore empirical and covers the invariants the oracle checks (\cref{sec:oracle}).

\emph{Remaining failures.} \Cref{S-tab:failures} traces each remaining failure to its cause. No retrieval miss, replay error or crash inconsistency remained. Recall failed in generation, where F4 hedged between values, ignored a retrieved memory or used the distractor, and its own live summaries lost 19.6\% of values. State control failed only at its edges: display names, which a canonicaliser placed before the barrier resolves, and narration after a blocked change (3.6\% of live F4 turns by the proxy, 8.0\% judged), which one repair call did not fix and which is better derived from committed events. Leaked secrets, player actions and the content of state, flag, journal and clue events lie outside the audit. The results support treating LLM output as untrusted input to a state machine that canonicalises references, validates per turn, is audited by an independent checker and recovers from a snapshot plus the logged suffix.

\section{Threats to Validity}\label{sec:limits}

The reported run used sample-size level 5 of twelve, with 14 live sessions per condition, and the three further backbones ran at level 2 on a four-world subset. Scoring is automatic: the contradiction judge that passed its controls is an LLM, and blinded sheets for two human raters are released for later labelling. The leak scorer and the desynchronisation proxy match keywords, and intent-level false rejection counts exact names only, so it bounds the true rate from below. W3 was written by the authors, players are scripted, the models have at most 7B parameters, the released game's hosted model was not evaluated, and B4 and B5 reproduce retrieval rules rather than full systems. F4v1 differs from F4 in validator, prompt, packing and repair at once (A8 isolates packing), the two barriers differ in both per-turn checking and the currency rule, and repair is isolated only by pairing drafts with repaired replies. With 14 sessions per cell, the live tests (R3, R4, H6) can detect only large effects, so H6 reports the absence of a significant interaction rather than equivalence. All conclusions apply to the tested worlds, models and invariants.

%=====================================================================
\section{Conclusion}\label{sec:conclusion}

This paper evaluated an engine that combines scoped dual-tier memory with validated, event-sourced state, against independent baselines at an equal budget and against its own earlier version. On the tested worlds and models, four results hold: long-term retrieval keeps recall level across 160 turns where a rolling context of equal size forgets, the barrier committed no violation of the eight audited invariants for any model or random proposal, memory and control showed no detectable interaction, and recovery from a snapshot plus the logged suffix succeeded in all 300 simulated crashes. The evaluation also shows where further gains lie. Flat vector memory recalled more than scoped memory, which did not improve on its earlier version, grounding by display name led the barrier to reject a fifth of lawful requests until canonicalised, and a single rewrite of a rejected reply did not reduce contradictions. Next steps are to canonicalise references in the released engine, gather human labels, derive narration from committed events and probe recall away from the place where a fact was told.
