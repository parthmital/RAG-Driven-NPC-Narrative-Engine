\pdfbookmark[1]{Abstract}{abstract}
\begin{abstract}
Large language models let non-player characters hold conversations, but they forget early facts, propose changes that break game rules, and cost more as context grows. We present \Sys{}, a dialogue engine that separates generation from state control: a dual-tier memory whose retrieval is scoped to the current location and character, and an event-sourced world state in which every proposed change must pass a symbolic validation barrier before commit. We compare it with six memory baselines at an equal budget, including the retrieval rule of the base paper, Generative Agents, in a memory-by-control factorial with seven ablations, on seven worlds and four models, and audit every committed change with an invariant oracle that shares no code with the validator. With a 7-billion-parameter backbone, it recalled 83.0\% of facts 20 or more turns old on held-out worlds, against 0.0\% for a rolling context and 63.0\% for the base paper's rule, but not more than flat vector memory (84.3\%) or its earlier version (88.6\%). Scoping raised mean reciprocal rank from 0.742 to 0.910. No output committed a state violation through the barrier, which rejected 0.7\% of lawful live requests, and recovery was exact after all 300 simulated crashes. These results are preliminary.
\end{abstract}

Large language models, non-player characters, long-term memory, event sourcing, runtime verification.
\end{IEEEkeywords}

\section{Introduction}\label{sec:intro}

\IEEEPARstart{T}{ext}-centric games mediate navigation, object interaction and character dialogue through language, so a text world stays consistent only through an explicit symbolic state. Dialogue trees and finite-state machines obey the rules at negligible cost but restrict players to predefined choices. LLMs remove that restriction, and surveys of LLMs in games identify the coupling of generated text to game state as an open problem \cite{gallotta2024llmgames}.

Three failure modes stand in the way. First, \emph{long-horizon forgetting}: facts outside a bounded context are lost, facts inside a long context are used unevenly \cite{liu2024lost}, and very long-term conversational memory remains weak even with retrieval \cite{maharana2024locomo,wu2025longmemeval}. Second, \emph{invariant violations}: LLMs are unreliable simulators of state transitions \cite{wang2024worldsim,kim2023entity} and lose narrative commitments \cite{ma2026ncp}, so unchecked they move players between unconnected rooms, invent items and grant unearned money. Third, \emph{cost growth}: full history, or several reflective LLM calls per turn \cite{park2023generative,shinn2023reflexion}, raises tokens and latency.

We evaluate an engine that separates generation from state control and compare it with the base paper, Generative Agents \cite{park2023generative}. Its components (a turn buffer, dense retrieval, schema-constrained output, a rule validator, an append-only event log and a deterministic reducer) are individually standard, so the contribution is an evaluation that isolates what each mechanism buys, against independent baselines, with its costs measured. It asks five questions. \textbf{RQ1}: does scoped dual-tier memory improve long-range recall per prompt token over rolling-context, vector-memory and generic retrieval agents? \textbf{RQ2}: does a pre-commit validation barrier over event-sourced state reduce committed invariant violations, and at what cost in false rejections and dialogue--state desynchronisation? \textbf{RQ3}: do memory and control contribute independently? \textbf{RQ4}: what latency and tokens does each component add? \textbf{RQ5}: do the effects hold across worlds of different authorship, genre and scale, and across backbones? The contributions are:
\begin{enumerate}[leftmargin=*]
  \item a formal account of the engine as implemented, including the post-filter limit of its scoped retrieval (\cref{sec:formal}),
  \item a \emph{paired four-way commit protocol}: each LLM output is committed through the corrected barrier, the earlier barrier, the reducer alone and by direct writes, and audited by an eight-invariant oracle that imports nothing from the validator, with a lawful \emph{twin} for every attack (\cref{sec:protocol}),
  \item a seven-world benchmark from four families and a single-notebook harness that reports recall, retrieval quality, violations, false rejection, desynchronisation, latency, tokens and replay consistency with pre-registered hypotheses (\cref{sec:setup}),
  \item findings from four runs: the defects the protocol exposed in the first version, a paired before-and-after measurement of their corrections, including a loss of recall they introduced, and the hypotheses the corrected system does not support (\cref{sec:results}).
\end{enumerate}
The supplementary material holds the algorithms, the dataset, the run configuration and audit, and every secondary result. Its sections, tables and figures are numbered with an S prefix.

\section{Literature Survey}\label{sec:related}

\emph{Grounded dialogue and text games.} LIGHT conditions dialogue on rooms, objects and personas in a crowd-written fantasy world \cite{urbanek2019light}, and goal-driven LIGHT agents were trained with reinforcement learning \cite{ammanabrolu2021dragon}, but neither keeps a validated world state over long sessions. TextWorld \cite{cote2019textworld} and Jericho \cite{hausknecht2020jericho} enforce rules but parse a constrained command language with no open NPC dialogue. Callison-Burch et al.~\cite{callisonburch2022dnd} framed Dungeons and Dragons as a dialogue challenge including state prediction, and STORIUM anchors collaborative stories with structured cards \cite{akoury2020storium}.

\subsection{Base paper: Generative Agents}\label{sec:base}
Generative Agents \cite{park2023generative} is the most direct prior architecture for LLM-driven characters with long-term memory in a game-like world. Twenty-five agents in a sandbox town keep a \emph{memory stream} of natural-language observations. Retrieval scores each memory as the equally weighted sum of min-max-normalised recency (decay 0.995 per sandbox hour), importance (an integer from 1 to 10 that the LLM assigns on creation) and relevance (cosine similarity), and reflections are synthesised when summed importance exceeds 150. Its evaluation ranks believability: 100 human evaluators ranked interview answers of the full architecture and its ablations. Three properties motivate this work. Memory is not bound to a validated symbolic state, and the paper reports embellished memories. Memory is expensive: every write costs an LLM call, and two simulated days of 25 agents cost thousands of dollars in token credits. Finally, neither recall of established facts nor rule violations is measured, at a matched token budget or otherwise.

\emph{Memory for LLM agents.} Reflexion stores verbal self-reflections \cite{shinn2023reflexion}, and summarising earlier sessions helps multi-session chat \cite{xu2022goldfish}. Later systems add forgetting curves \cite{zhong2024memorybank}, knowledge-graph indexing \cite{gutierrez2024hipporag}, linked notes \cite{xu2025amem}, multi-granularity summaries refined by reinforcement learning \cite{tan2025rmm} and compressed memory units \cite{liu2026simplemem}. Benchmarks show that long-term memory is far from solved \cite{maharana2024locomo,wu2025longmemeval}, and surveys organise the design space \cite{sumers2024coala,zhang2025memorysurvey}. None binds memory to a validated symbolic state or compares designs at a matched token budget in a game.

\emph{Retrieval and long context.} Retrieval-augmented generation conditions generation on passages from a dense index \cite{lewis2020rag} but ranks by similarity alone, with no notion of a turn's spatial or social scope. Longer contexts are no substitute, since models use their middle poorly \cite{liu2024lost}, and ReAct keeps a growing scratchpad \cite{yao2023react}. Scoping is a filtered nearest-neighbour query, and post-filtering a global top-$k$ loses in-scope neighbours, which motivates filter-aware indices \cite{gollapudi2023filtered} (\cref{prop:postfilter}).

\emph{State tracking and verifier-gated generation.} LLMs track entities imperfectly \cite{kim2023entity} and simulate text worlds unreliably \cite{wang2024worldsim}. LLM-Modulo argues for external model-based verifiers of LLM proposals \cite{kambhampati2024llmmodulo}, grammar-constrained decoding guarantees syntax but not legality \cite{geng2023gcd}, and prompt injection shows that model output cannot be trusted to follow its instructions \cite{greshake2023indirect}. Event sourcing derives state from an append-only log in industrial systems that need an auditable history \cite{overeem2021eventsourcing}.

\emph{LLM NPCs and narrative games.} PANGeA lets the LLM itself judge player input against design rules \cite{buongiorno2024pangea}, and Phillips et al.\ advance goal-based conversation states with an LLM that reads the dialogue history \cite{phillips2025goal}. SceneCraft generates branching NPC scenes \cite{kumaran2023scenecraft}, and CALYPSO supports Dungeon Masters with grounded LLM text \cite{zhu2023calypso}. NCP-Bench found that the best model kept its narrative commitments in 42\% of runs after 20 turns, with fact-conflict rates of 40\% to 68\%, as judged by LLM auditors \cite{ma2026ncp}. \Cref{tab:related} contrasts these systems.

\section{Research Gap}\label{sec:gap}

The survey leaves five gaps. \textbf{RG1:} memory is not bound to validated state (\cref{tab:related}). \textbf{RG2:} in-game state changes are judged by a model \cite{buongiorno2024pangea,phillips2025goal} or not at all, so symbolic pre-commit validation of LLM-proposed mutations is unevaluated in NPC dialogue. \textbf{RG3:} violations are scored by the component under test or by LLM auditors that can err on ambiguous text \cite{ma2026ncp}, never by a rule checker sharing no code with the validator on identical outputs. \textbf{RG4:} memory designs are rarely compared at an equal prompt-token budget, and the base paper reports cost only as token credits. \textbf{RG5:} false rejection, dialogue that contradicts rejected changes, and crash recovery are not reported with recall and violations. RQ1 to RQ5 address these gaps.

\section{Proposed Methodology}\label{sec:method}

\subsection{Formal model}\label{sec:formal}
The model is the one the code implements. Module paths refer to \repolink{\repo/tree/\evalcommit/Backend}{\code{Backend/}} at the evaluated commit.

\begin{definition}[World state]\label{def:state}
A world state is a tuple $S=(\mathcal{L},A,\mathcal{N},\mathcal{O},\pi,\iota,c,R,J,t)$ where $\mathcal{L}$ is the set of locations with directed adjacency $A\subseteq\mathcal{L}\times\mathcal{L}$, $\mathcal{N}$ the NPCs (location, persona, knowledge, conditional secrets, \code{alive} flag), and $\mathcal{O}$ the objects (location in $\mathcal{L}\cup\{\bot\}$, owner). The player's location is $\pi\in\mathcal{L}$, the inventory $\iota$ and the currency $c\in\mathbb{Z}_{\ge 0}$. The trust map is $R:\mathcal{N}\times(\mathcal{N}\cup\{\text{player}\})\to[-100,100]$, the journal $J$ and the turn $t$ (\bsrc{schemas/world_state.py}).
\end{definition}
The seed $S_0$ fixes the canonical entity sets $\mathcal{L}_0,\mathcal{N}_0,\mathcal{O}_0$, and the active NPC and player identity are restored from events, so the whole stored state is derived from the log.

\subsubsection{Events, reduction and replay}
An event $e=(\mathit{id},t,\tau,p,\mathit{ts})$ has one of 14 types $\tau$ (\bsrc{schemas/events.py}). The reducer $\delta$ (\bsrc{core/reducer.py}) deep-copies the state and applies one event, ignoring moves to unknown locations, clamping trust to $[-100,100]$ and flooring currency at zero, so
\begin{equation}\label{eq:fold}
S_{T}=\foldl(\delta,S_0,[e_1,\dots,e_T]),\qquad S_{i}=\delta(S_{i-1},e_i).
\end{equation}
Events are appended to SQLite in one transaction per turn, and every $\Delta=16$ turns a snapshot $(S_k,\mathit{id}_k)$ is written atomically.

\begin{proposition}[Replay and snapshot equivalence]\label{prop:replay}
If (i) $\delta$ depends only on $(S,e)$ and (ii) every change to the hashed state is a logged event applied by $\delta$, then for a snapshot after event $k$, $\foldl(\delta,S_0,e_{1..T})=\foldl(\delta,S_k,e_{k+1..T})$.
\end{proposition}
\begin{proof}
A left fold over a concatenated list folds the suffix from the prefix's result, which is $S_k$. Condition (i) holds because the reducer's only time-dependent value, a journal timestamp, is read from the persisted event. Condition (ii) failed in the Review-02 version for the active NPC, which is now an event field.
\end{proof}
Recovery from the latest snapshot costs $O(|S|+r)$ for the $r$ events after it. The corrected load path (\code{recover\_state}, \bsrc{core/recovery.py}) returns $\foldl(\delta,S_k,e_{k+1..T})$, while the Review-02 path returned $S_k$ and discarded every later event.

\subsubsection{Proposals and the validation barrier}
Each turn the LLM returns one JSON object validated by a Pydantic schema: dialogue, narration, a one-sentence memory summary and a list of proposals $P_t=[(\tau_j,p_j)]$. The barrier (\bsrc{game/validator.py}) checks them \emph{in order against a running state} $\hat S_0=S_t$, $\hat S_j=\delta(\hat S_{j-1},e(\tau_j,p_j))$ when accepted, and commits
\begin{equation}\label{eq:commit}
\begin{aligned}
E_t&=[\,e(\tau_j,p_j)\;:\;V(\tau_j,p_j,\hat S_{j-1},S_t)\,],\\
S_{t+1}&=\foldl(\delta,S_t,[e_{\text{speech}}]\mathbin{+\!\!+}E_t).
\end{aligned}
\end{equation}
$V$ requires a canonical, adjacent destination and at most one move per turn, a canonical NPC and a total trust change within $\pm20$ per NPC, a canonical object at the player's location for a take, possession or presence for NPC drops and takes, connected NPC moves, a canonical target for state updates, and integer currency deltas whose total spending stays within the opening balance $c(S_t)$ and whose net gain is at most 50. Engine-only event types and new entities are rejected. After a rejection, a repair node asks the model once to rewrite the reply so that it does not describe the rejected change. The Review-02 barrier, the ``before'' condition, checked each proposal independently against $S_t$, did not bound currency gains and had no repair.

\subsubsection{Invariants audited by the oracle}\label{sec:oracle}
The evaluation's oracle re-derives facts from $(S_{\text{pre}},S_{\text{post}},\text{committed mutations})$ and checks eight invariants written from the specification, not the validator. With $\mathcal{A}$ the undirected closure of the seed adjacency: (O1) entity sets equal the seed's and all references are canonical, (O2) each object is in exactly one place, (O3) $\pi_{\text{post}}=\pi_{\text{pre}}$ or $(\pi_{\text{pre}},\pi_{\text{post}})\in\mathcal{A}$, (O4) a newly held object was at the player's location, on the floor or held by an NPC there, and is held once, (O5) objects move only to the player's location and NPCs only along $\mathcal{A}$, (O6) $|R_{\text{post}}(n,\text{player})-R_{\text{pre}}(n,\text{player})|\le 20$, (O7) spending $\le c_{\text{pre}}$ and $c_{\text{post}}\ge 0$, and (O8) $c_{\text{post}}-c_{\text{pre}}\le 50$, a bound the Review-02 validator did not implement.

\subsubsection{Scoped dual-tier memory}\label{sec:memory-formal}
Long-term memory holds entries $m_i=(\mathbf{v}_i,x_i,t_i,\ell_i,n_i)$: the L2-normalised embedding of the player input under all-MiniLM-L12-v2 \cite{reimers2019sbert,wang2020minilm} ($d=384$), the model's memory summary, the turn, the player's location and the active NPC. An exact inner-product FAISS index \cite{johnson2021faiss} returns $\topk_m(\mathbf{q})$, the $m$ most similar entries. With the scope predicate
\begin{equation}\label{eq:scope}
\phi_{\ell,n}(m_i)=\bigl(\ell_i=\varnothing\lor\ell_i=\ell\bigr)\land\bigl(n_i=\varnothing\lor n_i=n\bigr),
\end{equation}
over-fetch $f=5$, threshold $\theta=3$ and $k=6$, retrieval is
\begin{equation}\label{eq:retrieve}
\mathcal{R}(\mathbf{q})=\begin{cases}
\operatorname{first}_k\bigl[m\in\topk_{\min(fk,|M|)}(\mathbf{q}) : \phi_{\ell,n}(m)\bigr]\\
\qquad\text{if this list has}\ \ge\theta\ \text{entries},\\
\topk_k(\mathbf{q})\quad\text{otherwise (fallback)}.
\end{cases}
\end{equation}
The short-term tier is a buffer of the last $B_s=8$ turns, and the store keeps its newest 500 entries when it passes 1{,}000. Memories and buffer share one budget of 1{,}600 characters (\bsrc{llm/prompt_builder.py}): the newest two turns first, then memories in rank order, then older turns, and a memory of a turn already in the history is dropped. The prompt also states the validator's limits from the same constants and shows an NPC's secrets once its trust reaches 60.

\begin{proposition}[Post-filter reachability]\label{prop:postfilter}
An in-scope entry can be returned by the scoped branch of \eqref{eq:retrieve} only if its similarity rank among all entries is at most $fk=30$, so scoped recall falls below exact filtered search when more than $fk-1$ out-of-scope entries are more similar.
\end{proposition}
\begin{proof}
The scoped branch inspects only $\topk_{fk}(\mathbf{q})$.
\end{proof}

F4v1 is the Review-02 system on the corrected reducer, event store and commit node.

\subsection{Paired four-way commit protocol}\label{sec:protocol}
Request seeds depend on the probe or turn, never on the condition, so identical prompts receive identical outputs. Each probe's parsed output is committed four ways (corrected barrier, Review-02 barrier, reducer alone, direct writes) and audited by the oracle, so differences between modes are due to the commit path alone. Lawfulness is judged by the oracle on a single-proposal transition, so false-rejection and validator-gap rates do not depend on the validator's verdicts (Algorithm~\ref{S-alg:protocol}).

\subsection{Metrics}\label{sec:metrics}
Recall is the share of probes answered with the planted key word. With $r_j$ the rank of probe $j$'s gold memory, $\text{MRR@}k=\frac1n\sum_j\mathds{1}[r_j\le k]\,r_j^{-1}$ and $\text{Recall@}k=\frac1n\sum_j\mathds{1}[r_j\le k]$, computed on probes older than the 8-turn buffer, because packing drops a memory whose turn is buffered. Rolling conditions report the \emph{gold-in-prompt} rate instead. \emph{Attack success} is the share of attacks whose post-state violates an invariant (a secret leak for secret extraction), \emph{false rejection} the share of lawful twin proposals rejected, and the \emph{validator gap} the share of unlawful proposals accepted. The \emph{violation rate} is 100 times the number of turns whose post-state violates an invariant over the committed non-speech mutations. Because the oracle audits the whole post-state, persistent corruption is flagged on every later turn, so live rates can exceed 100. \emph{Desynchronisation} flags a turn whose dialogue lacks a refusal cue after a rejection, or claims an arrival the state did not commit, and a \emph{contradiction judge} (Qwen2.5-7B-Instruct, another model family) labels replies that claim uncommitted changes. \emph{Replay consistency} compares SHA-256 hashes of the rebuilt and live states, and a \emph{crash trial} stops a commit at a random point and compares the recovered state with the last committed one.

\subsection{Statistical analysis}\label{sec:stats}
Intervals are 95\% cluster-bootstrap percentile intervals with 10{,}000 resamples \cite{efron1979,field2007clustered}, clustered on session or probe, with ratios bootstrapped as ratios of resampled sums. Paired binary outcomes use the exact McNemar test \cite{mcnemar1947} and paired continuous outcomes the Wilcoxon signed-rank test \cite{wilcoxon1945}. The six confirmatory tests (H1 to H3) are Holm-corrected \cite{holm1979}. The factorial is modelled on live turns as
\begin{multline}\label{eq:glmm}
\operatorname{logit}\Pr(y=1)=\beta_0+\beta_M M+\beta_C C\\
+\beta_{MC}MC+u_{\text{world}}+v_{\text{session}},
\end{multline}
with Gaussian random intercepts, fitted by variational Bayes in statsmodels \cite{seabold2010statsmodels}. Its $p$ values are approximate posterior summaries, not Wald tests.

\subsection{Hypotheses}\label{sec:hyp}
Stated before the run, each against the strongest applicable baseline and supported only if the corrected effect is significant with the predicted sign or its threshold is met. \textbf{H1}: F4 recall at $a\ge20$ exceeds B1 at equal budget, and B2 and B3 at equal or lower token cost. \textbf{H2}: scoping plus fallback gives higher MRR@6 than B2. \textbf{H3}: the barrier reduces committed violations on probes and in live sessions. \textbf{H4}: false rejection is at most 5\% and validation adds under 5\,ms at P95. \textbf{H5}: replay reproduces the live state in every event-sourced session. \textbf{H6}: memory mainly affects recall and control violations, with small interaction. \textbf{H7}: the H1 and H3 directions hold on W2, W3 and W4 and on two other model families. Four tests compare the system with its Review-02 version: \textbf{R1} currency, \textbf{R2} crash recovery, \textbf{R3} contradictions and \textbf{R4} live violations.

\section{Dataset Description and Usage}\label{sec:setup}

The benchmark is generated deterministically by the evaluation notebook from a master seed (\cref{S-sec:dataset-ext}). It has seven worlds in four families (\cref{S-tab:worlds}): W1, the in-house development world of 8 locations, W2a to W2c (16 to 32 locations) converted from the crowd-written LIGHT environment \cite{urbanek2019light} (CC BY-NC 4.0), W3, a 24-location science-fiction station written in the notebook, and the procedural W4-32 and W4-128. No setting was tuned on W2 to W4. \emph{Recall sessions} are teacher-forced scripts of 50, 100 or 200 turns in which facts are planted with an NPC and probed 5 to 160 turns later, each with a paraphrased distractor told to another NPC, so every condition sees the same history. Each condition answers 630 probes, 540 on held-out worlds, of which 324 have $a\ge20$. \emph{Adversarial probes} cover seven attack categories (teleportation, fabrication, theft, trust inflation, currency, prompt injection \cite{greshake2023indirect} and secret extraction), each with a lawful twin, giving 490 attacks and 470 twins, each posed under five contexts (4{,}800 outputs). \emph{Live sessions} run the real backend graph for 39 turns with plants, walks, trades, six attacks and four late probes, giving 14 sessions per condition. The data, predictions, metrics and blinded annotation sheets are released with the code.

%=====================================================================
\section{Novelty}\label{sec:novelty}

We claim no novelty for the engine's components. Against the base paper, the engine scopes retrieval by location and NPC with no LLM call per memory write, binds every model-proposed change to a typed, event-sourced state through a symbolic barrier and a pure reducer, and is evaluated by automatic, paired, oracle-audited metrics at a matched token budget instead of believability rankings. To our knowledge, no earlier evaluation pairs symbolic pre-commit validation with an independent oracle on identical outputs. It yields three new findings. (i) Of the 6.4 points of attack success under direct writes, the reducer's own semantics remove 4.2, the Review-02 validator 1.0 more and the corrected validator the remaining 1.2, so validator and reducer must be evaluated as a pair. (ii) An oracle written from the specification exposed a currency rule the first validator never implemented (a 59.1\% validator gap on currency proposals) and confirms its repair. (iii) The costs of control are measured: 0.7\% false rejection of lawful live requests, validation below 2\,ms, a repair that does not reduce judged contradictions on the turns it rewrites, and a loss of recall.

%=====================================================================
\section{Algorithms}\label{sec:algorithms}

Three algorithms define the system and its evaluation. Algorithm~\ref{S-alg:turn} is one turn of the engine, following nodes 1 to 9 of \cref{fig:arch}, Algorithm~\ref{S-alg:retrieve} is the retrieval of \eqref{eq:retrieve}, and Algorithm~\ref{S-alg:protocol} is the paired four-way commit and audit. With $|M|\le 1000$ entries and $p$ proposals per turn, exact search is $O(|M|d)$, validation $O(p)$ lookups plus one reduction per accepted proposal, reduction $O(p\,|S|)$, and recovery $O(|S|+r)$.

%=====================================================================
\section{Implementation}\label{sec:impl}

The engine has four tiers: a React and TypeScript client over a WebSocket, a FastAPI service with per-session locks running a compiled nine-node LangGraph \code{StateGraph} (\bsrc{graph/definition.py}), the barrier, and storage (the SQLite event log and snapshots, the FAISS store and the buffer). The shipped game uses a hosted model (Groq, \code{openai/gpt-oss-120b}, temperature 0.35), and the evaluation self-hosts models with vLLM \cite{kwon2023vllm}. The evaluation notebook \msrc{notebooks/npc-memory-state-benchmark.ipynb} imports the real backend modules of the evaluated commit from a hashed bundle, so only the baselines, the oracle and the generators are new code. The reported run used two Tesla T4 GPUs on Kaggle for 7.65 hours, \hfmodel{IFM/K2-Horizon-7B} as the primary backbone, and level 2 of eight pre-declared sample sizes (\cref{S-tab:config,S-tab:ladder}). Auditing the two earlier runs found and fixed four measurement defects in the notebook (\cref{S-sec:gaps}).

\subsection{Retrieval quality}\label{sec:retrieval}
Scoping changed \emph{ranking} more than \emph{reach}. On the 432 held-out probes older than the buffer, F4, B2, A2 and A4 placed the gold memory in their retrieved list every time, but F4 ranked it higher (MRR@6 0.910 against 0.742 for B2 and 0.732 for the unscoped ablation A3) and kept the distractor out of 46\% of prompts, against 1\% for B2. Disabling the fallback (A4) raised MRR@6 to 0.954, since the fallback replaces a short scoped list with unscoped neighbours. Retrieval sweeps, budget scaling and three sampling seeds confirm these findings (\cref{S-sec:retrieval-ext}).

\subsection{Live factorial, ablations and recovery}\label{sec:factorial}
In live sessions (\cref{S-tab:factorial}), direct writes left 471 of 546 F1 turns and 469 of 546 F3 turns flagged, because the player was left in a non-existent location on about 30 of 39 turns. Neither corrected-barrier condition had a flagged turn, and F4v1 had four. The barrier raised desynchronisation from about 3\% of turns to 12.5\% (F2) and 9.5\% (F4), below the 18.9\% of F4v1. Live recall was 37.5\% (F3) and 46.4\% (F4), well below teacher-forced recall, and per session both memory and control effects were significant ($p\le0.0012$). The mixed model (\cref{S-tab:glmm}) confirms that memory dominates recall and control violations, but also finds a positive memory-by-control interaction on recall ($\beta_{MC}=1.317$, $p=3.1\times10^{-6}$). Among the ablations (\cref{S-tab:ablations}), only removing long-term memory (A1) was catastrophic (0.0\%), removing the buffer (A2, 86.4\%) or the fallback (A4, 83.0\%) did not lower recall, and removing the validator (A5) let violations through on probes (5.0 per 100 transitions) and in live play (3.9). Every event-sourced session replayed exactly. Full replay took 243.2\,ms at turn 160 against 1.1 to 1.4\,ms for snapshot loading, and over 300 randomised crash trials the corrected load path was consistent in all 300, the Review-02 path in 77 (\cref{S-tab:replay}).

\subsection{Comparison with the base paper}\label{sec:base-compare}
The evaluations use different worlds, models and metrics, so the comparison is architectural (\cref{S-tab:base}). In both systems memory is necessary: removing observation, reflection and planning lowered the base paper's TrueSkill rating from 29.89 to 21.21, and removing long-term memory here lowered recall at $a\ge20$ from 83.0\% to 0.0\%. The base paper's retrieval rule forgets under a budget (B4, 63.0\%), while relevance alone (B2) recalls as well as scoping. State control has no counterpart in the base paper, which reports embellishment but no rule violations. None of F4's recall failures came from retrieval: it had no retrieval miss, and in all 84 ``hit but ignored'' cases the gold turn was in the prompt (\cref{S-tab:errors}).

%=====================================================================
\section{Discussion}\label{sec:discussion}

\emph{Memory.} At an equal budget, flat vector and forgetting-curve memories recall about as well as scoping, whose measurable benefits are ranking and distractor exclusion on a benchmark that favours it (facts are probed with the NPC who heard them). At scale, post-filtering the global top-30 can drop in-scope memories that a filtered index keeps (\cref{prop:postfilter}, \cite{gollapudi2023filtered}).

\emph{State control.} The barrier is only as good as its rule set: the oracle found a missing currency rule, and with it and per-turn checking no violation got through for any model, at a cost of 0.7\% of lawful live requests. Models of other families proposed unlawful changes far more often, which is where a symbolic barrier matters most. Blocking still leaves the narration wrong on the turn itself, so the repair prompt, or narration generated from committed events, needs work.

\emph{For practitioners.} Treat LLM output as untrusted input to a state machine, keep the reducer defensive behind a per-turn validator, audit with a checker that shares no validator code, and recover by snapshot plus suffix.

%=====================================================================
\section{Limitations and Threats to Validity}\label{sec:limits}

The run used level 2 of eight sample sizes, so live intervals are wide. Scoring is automatic, the contradiction judge is an LLM, and the blinded sheets for two human raters are not yet filled. The retrieval scoring rule was fixed after the first Review-03 run. W3 was not independently authored, players are scripted, the models have at most 7B parameters, and the game's hosted model was not evaluated. B4 and B5 re-implement retrieval rules, not full systems, and F4v1 changes validator, prompt, packing and repair together. Claims are restricted to the tested worlds and models.

%=====================================================================
\section{Conclusion}\label{sec:conclusion}

We tested an engine that pairs scoped dual-tier memory with validated, event-sourced state, against independent baselines at an equal budget and against its own earlier version. Three claims are supported. Scoped long-term retrieval keeps recall high and flat over 160 turns where a rolling context of equal size forgets everything after ten, and ranks the right memory higher than flat vector memory. A pre-commit barrier over an event-sourced log committed no state violation for any model while rejecting few lawful requests. Snapshot-plus-suffix recovery reproduced the committed state after every simulated crash. Three claims are not supported: the memory is not better than flat vector or forgetting-curve memory and recalls less than its earlier version, memory and control are not independent, and one rewrite of a rejected reply did not reduce contradictions on the turns it rewrote. Future work should rerun at a larger sample size, collect human labels, generate narration from committed events, locate the recall loss, and probe recall away from where a fact was told.
