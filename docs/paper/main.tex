\begin{abstract}
Large language models (LLMs) let non-player characters (NPCs) hold open-ended conversations, but they forget facts established early in a session, propose world changes that break game rules, and cost more as context grows. We present \Sys{}, an NPC dialogue engine that separates generation from state control: a dual-tier memory (an 8-turn buffer plus a FAISS store whose retrieval is scoped to the current location and NPC, packed into one context budget) and an event-sourced world state in which every LLM-proposed mutation must pass a symbolic pre-commit validation barrier, followed by dialogue repair when a proposal is rejected. Taking Generative Agents as the base paper, we compare the engine with rolling-context, flat vector-memory, generic retrieval, scored memory-stream, forgetting-curve and full-history baselines at an equal memory budget, in a $2\times2$ memory-by-control factorial with seven ablations, on seven worlds of 8 to 128 locations, with four models from three families. Every model output is committed four ways and audited by an invariant oracle that shares no code with the validator, and the system is paired against its own earlier version on the same scenarios. With a self-hosted 7B backbone the system recalled \ci{83.0}{79.4}{86.7}\% of facts 20 or more turns old on held-out worlds, against 0.0\% for a rolling context of equal budget and 63.0\% for a Generative-Agents-style memory stream; it did not beat flat vector memory (84.3\%) or a forgetting-curve memory (79.9\%), and it recalled significantly less than its own earlier version (88.6\%). Scored on facts older than the buffer, scoping raised MRR@6 from 0.742 to 0.910. On identical outputs, attack success was 6.4\% with direct writes and 1.2\% with the earlier validator, and no output committed a state violation or succeeded as an attack through the corrected barrier, which rejected 0.7\% of lawful live requests and removed every committed violation in live play. Snapshot-plus-suffix recovery made all 300 randomised crashes consistent, against 77 before. Dialogue repair did not reduce judged contradictions on the turns it rewrote, although the corrected system contradicted rejected changes on fewer live turns than its earlier version (13.8\% against 57.0\%). The results are preliminary: the run used the third of eight planned sample sizes and automatic scoring.
\end{abstract}

\section{Introduction}\label{sec:intro}

\IEEEPARstart{T}{ext}-centric games mediate navigation, object interaction and character dialogue entirely through language. Unlike graphical engines, where physics enforces spatial constraints, a text world can only stay consistent through an explicit symbolic state. Games have traditionally driven NPCs with dialogue trees and finite-state machines, which obey the rules at negligible cost but restrict players to predefined choices. LLMs remove that restriction, and surveys of LLMs in games identify the coupling of generated text to game mechanics and state as an open problem \cite{gallotta2024llmgames}.

Three failure modes stand in the way. First, \emph{long-horizon forgetting}: facts that fall out of a bounded context window are lost, and facts inside a long context are used unevenly \cite{liu2024lost}; very long-term conversational memory remains weak even with retrieval \cite{maharana2024locomo,wu2025longmemeval}. Second, \emph{invariant violations}: LLMs are unreliable simulators of state transitions \cite{wang2024worldsim,kim2023entity} and lose narrative commitments over long interactions \cite{ma2026ncp}; left unchecked they move players between unconnected rooms, invent items and grant unearned money. Third, \emph{cost growth}: appending full history, or running several reflective LLM calls per turn \cite{park2023generative,shinn2023reflexion}, raises tokens and latency per turn.

This paper evaluates an architecture that addresses all three by separating generation from state control (\cref{sec:method}), and compares it with the base paper, Generative Agents \cite{park2023generative} (\cref{sec:base}). Its components are individually standard: a turn buffer, dense retrieval, schema-constrained output, a rule validator, an append-only event log and a deterministic reducer. Our claim is therefore not that any component is new. The contribution is an evaluation that isolates what each mechanism buys, against independent baselines, with the costs it imposes measured rather than assumed.

\subsection{Research questions}
\textbf{RQ1} (memory): does scoped dual-tier memory improve long-range recall per prompt token over rolling-context, vector-memory and generic retrieval agents?
\textbf{RQ2} (state control): does a pre-commit validation barrier over event-sourced state reduce committed invariant violations, and at what cost in false rejections and dialogue--state desynchronisation?
\textbf{RQ3} (separability): do memory and control contribute independently?
\textbf{RQ4} (efficiency): what latency and tokens does each component add?
\textbf{RQ5} (generalisation): do the effects hold across worlds of different authorship, genre and scale, and across backbones?

\subsection{Contributions}
\begin{enumerate}[leftmargin=*]
  \item A formal account of the engine as implemented: the world state, the event reducer and its replay and snapshot properties, the scoped retrieval operator with its post-filter limitation, and the validation predicate, including the coverage gaps found in the code (\cref{sec:formal,sec:system}).
  \item A \emph{paired four-way commit protocol} with an \emph{independent oracle}: each LLM output is committed through the corrected barrier, through the earlier barrier, through the reducer alone and by direct writes, and the four post-states are audited by an eight-invariant oracle that imports nothing from the validator. Common random numbers make every control comparison exactly paired, and lawful \emph{twins} of every attack measure false rejection (\cref{sec:protocol}).
  \item A multi-world benchmark (four families, seven worlds, long-horizon sessions of 50 to 200 turns, seven attack categories) and a single-notebook harness that reports recall, retrieval quality, violations, false rejection, desynchronisation, latency, tokens and replay consistency together, with cluster-bootstrap intervals and pre-registered hypotheses (\cref{sec:setup,sec:repro}).
  \item Empirical findings from four runs: the defects that a paired, oracle-audited evaluation exposed in the first version (unbounded currency gains, a load path that discards the logged suffix, dialogue that contradicts rejected changes), a paired before-and-after measurement of their corrections, including a loss of recall that the corrections introduced, and the hypotheses that the corrected system does not support (\cref{sec:results,sec:discussion}).
\end{enumerate}

\section{Literature Survey}\label{sec:related}

\subsection{Grounded dialogue and text games}
LIGHT conditions dialogue on rooms, objects and personas in a crowd-written fantasy world \cite{urbanek2019light}, and goal-driven agents in LIGHT were trained with reinforcement learning over factorised speech and action spaces \cite{ammanabrolu2021dragon}. Neither keeps a persistent, validated world state over long sessions. TextWorld \cite{cote2019textworld} and Jericho \cite{hausknecht2020jericho} provide formally specified or human-authored games whose engines enforce rules, but they parse a constrained command language and have no open NPC dialogue. Callison-Burch et al.~\cite{callisonburch2022dnd} framed Dungeons and Dragons as a dialogue challenge including state prediction, and STORIUM anchors collaborative stories with structured cards \cite{akoury2020storium}.

\subsection{Base paper: Generative Agents}\label{sec:base}
We take Generative Agents \cite{park2023generative} as the base paper: it is the most direct prior architecture for LLM-driven characters with long-term memory in a game-like world. Twenty-five agents live in a sandbox town whose areas and objects form a tree. Each agent keeps a \emph{memory stream} of natural-language observations. Retrieval scores every memory as the equally weighted sum of three min-max-normalised terms: recency (exponential decay with factor 0.995 per sandbox hour since last access), importance (an integer from 1 to 10 that the LLM assigns when the memory is created) and relevance (cosine similarity of embeddings to a query); the top-ranked memories that fit the context window enter the prompt. Reflections, higher-level memories that the LLM synthesises when the summed importance of recent events exceeds 150, and plans are stored in the same stream. Agents act through natural-language statements that the engine maps onto the sandbox. The evaluation measures believability: 100 human evaluators ranked interview answers from the full architecture, three memory ablations and a crowdworker condition, and a two-day end-to-end simulation measured information diffusion, relationship formation and coordination.

Three properties of the base paper motivate this work. First, memory is not bound to a validated symbolic state: the paper describes no check of the agents' statements against game rules, and it reports embellished memories as a failure mode. Second, memory is expensive: every memory write costs an LLM call for importance, reflection costs more, and the authors report that simulating 25 agents for two days cost thousands of dollars in token credits. Third, the evaluation ranks believability rather than measuring recall of established facts or rule violations, and memory designs are not compared at a matched token budget. \Cref{sec:base-compare} compares the two systems.

\subsection{Memory for LLM agents}
Reflexion stores verbal self-reflections across trials \cite{shinn2023reflexion}. In multi-session chat, models that summarise and recall earlier sessions outperform standard encoder--decoders \cite{xu2022goldfish}. Later systems add forgetting curves \cite{zhong2024memorybank}, knowledge-graph indexing \cite{gutierrez2024hipporag}, self-organising linked notes \cite{xu2025amem}, multi-granularity summaries with retrieval refined by reinforcement learning \cite{tan2025rmm}, and compression of interactions into compact indexed memory units \cite{liu2026simplemem}. Benchmarks show that long-term memory is far from solved \cite{maharana2024locomo,wu2025longmemeval}, and surveys organise the design space \cite{sumers2024coala,zhang2025memorysurvey}. These systems store natural-language memories and most spend extra LLM calls per write; none binds memory to a validated symbolic state, and none is compared at a matched token budget in a game setting.

\subsection{Retrieval and long context}
Retrieval-augmented generation conditions generation on passages from a dense index \cite{lewis2020rag}; generic RAG ranks by similarity alone and has no notion of a turn's spatial or social scope. Extending the context is not a substitute: models use the middle of long contexts poorly \cite{liu2024lost}. ReAct keeps a growing scratchpad of observations and actions \cite{yao2023react}. Scoping by metadata is a filtered nearest-neighbour query; post-filtering a global top-$k$ is known to lose in-scope neighbours, which motivates filter-aware indices \cite{gollapudi2023filtered}. We analyse exactly this effect in the engine's retrieval (\cref{prop:postfilter}).

\subsection{State tracking and verifier-gated generation}
LLMs track entities imperfectly \cite{kim2023entity} and are unreliable text-world simulators \cite{wang2024worldsim}. The LLM-Modulo position argues that LLM proposals should be checked by external model-based verifiers \cite{kambhampati2024llmmodulo}; grammar-constrained decoding guarantees syntactic well-formedness but not semantic legality \cite{geng2023gcd}. Prompt injection shows that model output cannot be trusted to obey instructions in its context \cite{greshake2023indirect}. Event sourcing, where state is derived from an append-only log of events, is used in industrial systems that need an auditable history \cite{overeem2021eventsourcing}.

\subsection{LLM NPCs and narrative games, 2023 to 2026}
PANGeA generates RPG content with a memory system and a validator in which the LLM itself judges player input against design rules \cite{buongiorno2024pangea}. Phillips et al.\ model conversations as puzzles whose goal-based states are advanced by an LLM that reads the dialogue history \cite{phillips2025goal}, so state transitions are again judged by a model. SceneCraft generates branching NPC scenes from authorial instructions and converts them into a game scripting language \cite{kumaran2023scenecraft}, and CALYPSO supports Dungeon Masters with LLM-generated text grounded in an established game setting \cite{zhu2023calypso}. NCP-Bench measures how interactive narratives drift under adversarial player interventions: the best model kept its commitments in 42\% of runs after 20 turns, and fact-conflict rates ranged from 40\% to 68\% across models, as judged by LLM auditors \cite{ma2026ncp}.

\section{Research Gap}\label{sec:gap}

The survey leaves five gaps, which together define the problem this paper addresses.
\begin{enumerate}[leftmargin=*,label=RG\arabic*.]
  \item \textbf{Memory is not bound to validated state.} From the base paper's memory stream to compressed or graph-indexed memories, memory systems store natural-language text; none ties what an NPC remembers to a symbolic world state that the model cannot corrupt (\cref{tab:related}).
  \item \textbf{State changes are judged by a model or not at all.} In-game systems either let an LLM judge legality \cite{buongiorno2024pangea,phillips2025goal} or apply model output directly; symbolic pre-commit validation of LLM-proposed mutations has not been evaluated in NPC dialogue.
  \item \textbf{No independent audit.} Where violations are measured, they are scored by the component under test or by LLM auditors whose authors note that they can err on ambiguous text \cite{ma2026ncp}; no evaluation pairs identical model outputs across commit paths and scores them with a rule checker that shares no code with the validator.
  \item \textbf{No matched-cost comparison.} Memory designs are compared on accuracy, rarely at an equal prompt-token budget against a rolling context; the base paper reports cost only as thousands of dollars of token credits \cite{park2023generative}.
  \item \textbf{Costs of control are unmeasured.} False rejection of lawful requests, dialogue that contradicts rejected changes, and replay and crash recovery are not reported together with recall and violations.
\end{enumerate}
Five research questions follow from these gaps (\cref{sec:intro}); \cref{sec:method} gives the methodology that answers them and \cref{sec:novelty} states what is new.

\section{Proposed Methodology}\label{sec:method}

The methodology has two parts. The engine (\cref{sec:formal,sec:system}) separates language generation from state control: the LLM proposes dialogue and state changes, a scoped dual-tier memory supplies context, and only proposals that pass a symbolic barrier reach an event-sourced state. The evaluation (\cref{sec:conditions,sec:protocol,sec:metrics,sec:stats,sec:hyp}) isolates each mechanism in a factorial design with ablations, pairs every control comparison on identical model outputs, and scores violations with an independent oracle. The data it runs on is described in \cref{sec:setup}, the pseudocode in \cref{sec:algorithms}, and the implementation in \cref{sec:impl}.

\subsection{Formal model}\label{sec:formal}
The model below is the one the code implements; module paths refer to \href{\repo/tree/\evalcommit/Backend}{\code{Backend/}} at the evaluated commit.

\subsubsection{World state}
\begin{definition}[World state]\label{def:state}
A world state is a tuple $S=(\mathcal{L},A,\mathcal{N},\mathcal{O},\pi,\iota,c,R,J,t)$ where $\mathcal{L}$ is the set of locations with directed adjacency $A\subseteq\mathcal{L}\times\mathcal{L}$ (the \code{connected\_to} lists); $\mathcal{N}$ is the set of NPCs, each with a location, persona, knowledge, conditional secrets and an \code{alive} flag; $\mathcal{O}$ is the set of objects, each with a location in $\mathcal{L}\cup\{\bot\}$ and an owner; $\pi\in\mathcal{L}$ is the player's location, $\iota$ the inventory and $c\in\mathbb{Z}_{\ge 0}$ the currency; $R:\mathcal{N}\times(\mathcal{N}\cup\{\text{player}\})\to[-100,100]$ is the trust map; $J$ the journal; and $t$ the turn (\bsrc{schemas/world_state.py}).
\end{definition}
The seed $S_0$ fixes the canonical entity sets $\mathcal{L}_0,\mathcal{N}_0,\mathcal{O}_0$. The active NPC and the player's identity are restored from \code{NPC\_SPOKE} and \code{SESSION\_START} events, so the whole stored state is derived from the log.

\subsubsection{Events, reduction and replay}
An event is $e=(\mathit{id},t,\tau,p,\mathit{ts})$ with type $\tau$ from 14 types (\bsrc{schemas/events.py}) and payload $p$. The reducer $\delta$ (\bsrc{core/reducer.py}) deep-copies the state and applies one event; it ignores moves to unknown locations, clamps trust to $[-100,100]$, floors currency at zero, and ignores an NPC \code{location\_id} change to a non-canonical location. State after $T$ events is
\begin{equation}\label{eq:fold}
S_{T}=\foldl(\delta,S_0,[e_1,\dots,e_T]),\qquad S_{i}=\delta(S_{i-1},e_i).
\end{equation}
Events are appended to SQLite with autoincrement ids, one transaction per turn, and every $\Delta=16$ turns a snapshot $(S_k,\mathit{id}_k)$ is written atomically, where $\mathit{id}_k$ is the last event id (\bsrc{graph/definition.py}).

\begin{proposition}[Replay and snapshot equivalence]\label{prop:replay}
If (i) $\delta$ is a function of $(S,e)$ only and (ii) every change to the hashed part of the live state is made by applying a logged event with $\delta$, then for any snapshot taken after event $k$,
\begin{align*}
\foldl(\delta,S_0,e_{1..T})&=\foldl\bigl(\delta,\foldl(\delta,S_0,e_{1..k}),e_{k+1..T}\bigr)\\
&=\foldl(\delta,S_k,e_{k+1..T}).
\end{align*}
\end{proposition}
\begin{proof}
The first equality is the definition of a left fold over a concatenated list; the second substitutes the snapshot. Condition (i) holds in the code because the only time-dependent value the reducer writes, a journal entry's timestamp, is read from the event, which is persisted with it. In the Review-02 version, condition (ii) failed for the active NPC, which was set outside the log; it is now an event field.
\end{proof}
Recovery from the latest snapshot therefore costs $O(|S|+r)$ with $r$ the number of events after it, against $O(|S|+T)$ for a full fold. The load path (\bsrc{core/recovery.py}, \code{recover\_state}) returns $\foldl(\delta,S_k,e_{k+1..T})$, and a full fold when no usable snapshot exists or the snapshot is ahead of the log. The Review-02 load path returned $S_k$ and discarded every event after the last snapshot unless a per-turn auto-save happened to succeed. \Cref{sec:replay} measures both.

\subsubsection{Proposals and the validation barrier}
Each turn the LLM returns one JSON object validated by a Pydantic schema (\bsrc{schemas/llm_output.py}): dialogue, narration, a one-sentence memory summary, a list of proposals $P_t=[(\tau_j,p_j)]$ and a list of proposed new entities. The barrier (\bsrc{game/validator.py}) checks the proposals \emph{in order against a running state}: with $\hat S_0=S_t$, proposal $j$ is accepted when $V(\tau_j,p_j,\hat S_{j-1},S_t)$ holds, and then $\hat S_j=\delta(\hat S_{j-1},e(\tau_j,p_j))$; a rejected proposal leaves $\hat S_j=\hat S_{j-1}$. The turn commits
\begin{equation}\label{eq:commit}
\begin{aligned}
E_t&=[\,e(\tau_j,p_j)\;:\;V(\tau_j,p_j,\hat S_{j-1},S_t)\,],\\
S_{t+1}&=\foldl(\delta,S_t,[e_{\text{speech}}]\mathbin{+\!\!+}E_t).
\end{aligned}
\end{equation}
$V$ requires: a move's destination is canonical, adjacent to the current location and the turn's only move; a trust change names a canonical NPC and keeps that NPC's total change in the turn within $\pm20$; a taken object is canonical and lies at the player's location, and an NPC's drop or take checks possession or presence; an NPC move follows a connection; state and flag updates name a canonical target and a key; a journal entry has content; a currency delta is an integer, total spending in the turn does not exceed the opening balance $c(S_t)$, and the net gain in the turn does not exceed 50. Engine-only event types and any non-empty \code{new\_entities} list are rejected. When a proposal is rejected, a repair node asks the model once to rewrite the reply so that it does not describe the rejected change, and replaces it with a neutral narration if the rewrite does not parse (\bsrc{graph/definition.py}). The Review-02 barrier, which we evaluate as the ``before'' condition, checked every proposal independently against $S_t$, did not bound currency gains and did not repair the dialogue.

\subsubsection{Invariants audited by the oracle}\label{sec:oracle}
The evaluation's oracle (notebook section 4.1) re-derives facts from $(S_{\text{pre}},S_{\text{post}},\text{committed mutations})$ and checks eight invariants, written from the specification rather than the validator. With $\mathcal{L}_0,\mathcal{N}_0,\mathcal{O}_0$ from the seed and $\mathcal{A}$ the \emph{undirected} closure of the seed adjacency:
\begin{description}[leftmargin=2.4em,style=nextline]
  \item[O1 canonicity] post-state entity sets equal the seed's; the player, inventory and NPC locations reference canonical ids.
  \item[O2 conservation] each object is in exactly one place: a location, the inventory, or an NPC's possession.
  \item[O3 adjacency] $\pi_{\text{post}}=\pi_{\text{pre}}$ or $(\pi_{\text{pre}},\pi_{\text{post}})\in\mathcal{A}$.
  \item[O4 theft/duplication] a newly held object was at the player's location, on the floor or held by an NPC who is there, and is held once.
  \item[O5 relocation] objects move only to the player's location; NPCs move only along $\mathcal{A}$.
  \item[O6 trust bound] $|R_{\text{post}}(n,\text{player})-R_{\text{pre}}(n,\text{player})|\le 20$ for every NPC.
  \item[O7 solvency] total spending in the turn $\le c_{\text{pre}}$ and $c_{\text{post}}\ge 0$.
  \item[O8 unearned currency] $c_{\text{post}}-c_{\text{pre}}\le 50$.
\end{description}
O8 encodes a design bound that the Review-02 validator did not implement; the oracle found that gap in the Review-02 run, and the corrected validator now enforces it (\cref{sec:control}).

\subsubsection{Scoped dual-tier memory}\label{sec:memory-formal}
Long-term memory is a set of entries $m_i=(\mathbf{v}_i,x_i,t_i,\ell_i,n_i)$: a unit vector, the text shown to the model, the turn, a location and an NPC. On commit, $\mathbf{v}_i$ is the embedding of the \emph{player input} under \href{https://huggingface.co/sentence-transformers/all-MiniLM-L12-v2}{all-MiniLM-L12-v2} \cite{reimers2019sbert,wang2020minilm} ($d=384$, L2-normalised), $x_i$ is the model's memory summary (or the truncated input when absent), $\ell_i$ is the player's location after the turn's events and $n_i$ the active NPC. The index is an exact inner-product FAISS index \cite{johnson2021faiss}, so $\mathbf{q}^\top\mathbf{v}_i$ is cosine similarity. For query $\mathbf{q}$, current location $\ell$ and NPC $n$, let $\topk_m(\mathbf{q})$ be the $m$ most similar entries in descending order and define the scope predicate
\begin{equation}\label{eq:scope}
\phi_{\ell,n}(m_i)=\bigl(\ell_i=\varnothing\lor\ell_i=\ell\bigr)\land\bigl(n_i=\varnothing\lor n_i=n\bigr),
\end{equation}
where empty metadata acts as a wildcard. Scoped retrieval with over-fetch factor $f=5$ and threshold $\theta=3$ is
\begin{equation}\label{eq:retrieve}
\mathcal{R}(\mathbf{q})=\begin{cases}
\operatorname{first}_k\bigl[m\in\topk_{\min(fk,|M|)}(\mathbf{q}) : \phi_{\ell,n}(m)\bigr]\\
\qquad\text{if this list has}\ \ge\theta\ \text{entries},\\
\topk_k(\mathbf{q})\quad\text{otherwise (relaxation fallback)},
\end{cases}
\end{equation}
with $k=6$. The fallback \emph{replaces} the scoped list rather than extending it. The short-term tier is a ring buffer of the last $B_s=8$ turns. When $|M|>1000$ the store keeps its newest 500 entries. Memories and buffer share one budget of 1{,}600 characters (\code{pack\_context} in \bsrc{llm/prompt_builder.py}): the newest two turns are always kept, then retrieved memories in rank order, then older buffer turns, newest first, while the budget allows; a memory of a turn whose dialogue is already in the history is dropped as a duplicate.

\begin{proposition}[Post-filter reachability]\label{prop:postfilter}
An in-scope entry $m$ can be returned by the scoped branch of \eqref{eq:retrieve} only if its similarity rank among \emph{all} entries is at most $fk=30$. Hence scoped recall can fall below the recall of an exact filtered search whenever more than $fk-1$ out-of-scope entries are more similar to $\mathbf{q}$ than $m$.
\end{proposition}
\begin{proof}
The scoped branch filters $\topk_{fk}(\mathbf{q})$; entries outside it are never inspected.
\end{proof}

\noindent The prompt contains a fixed system block that states the validator's limits from the same configuration constants, the canonical state of the current location and active NPC (with the NPC's secrets once its trust in the player reaches 60), player identity, the packed memories and history, and the query, capped at 16{,}384 characters (\bsrc{llm/prompt_builder.py}).

\subsection{Turn pipeline}\label{sec:system}
\Cref{fig:arch} shows one turn. \subsection{Paired four-way commit protocol}\label{sec:protocol}
Request seeds depend on the probe or turn and never on the condition, so identical prompts receive identical outputs (common random numbers). For probes, the \emph{same} parsed output is then committed four ways (through the corrected barrier, through the Review-02 barrier, through the reducer alone, and by direct writes) and audited by the oracle of \cref{sec:oracle}, so differences between modes are attributable to the commit path alone. Lawfulness of a proposal is judged by the oracle on a single-proposal transition, which gives false-rejection and validator-gap rates that do not depend on the validator's own verdicts. \Cref{sec:alg-protocol} gives the procedure.

\subsection{Metrics}\label{sec:metrics}
Let $y_j\in\{0,1\}$ be correctness of recall probe $j$ and $r_j$ the rank of its gold memory among the retrieved list (undefined if absent).
\begin{align}
\text{Recall}&=\tfrac{1}{n}\textstyle\sum_j y_j,\notag\\
\text{MRR@}k&=\tfrac{1}{n}\textstyle\sum_j \mathds{1}[r_j\le k]\,r_j^{-1},\notag\\
\text{Recall@}k&=\tfrac{1}{n}\textstyle\sum_j \mathds{1}[r_j\le k].\label{eq:recall}
\end{align}
MRR@$k$ and Recall@$k$ are computed only on probes whose fact is older than the 8-turn buffer: the packing step drops a memory that duplicates a buffered turn, so a younger fact has no retrieval rank in F4 even when it is in the prompt. This rule was adopted after the first Review-03 run, which counted such probes as misses, and the reported run applies it as part of the notebook (\cref{sec:gaps}). For rolling conditions, the \emph{gold-in-prompt} rate (the plant turn is in the history or retrieved list) replaces MRR. For probes, \emph{attack success} is the share of attacks whose post-state violates an invariant (a secret leak for the secret category); \emph{false rejection} is $\sum$ lawful twin proposals rejected $/\sum$ lawful twin proposals; the \emph{validator gap} is $\sum$ unlawful proposals accepted $/\sum$ unlawful proposals over attacks and twins. The \emph{violation rate} is
\begin{multline}\label{eq:viol}
\text{Viol}/100=\\
100\cdot\frac{\sum_{\text{turns}}\mathds{1}[\text{post-state violates some invariant}]}{\sum_{\text{turns}}(\text{committed non-speech mutations})}.
\end{multline}
The oracle audits the whole post-state, so a corruption that persists (for example a player left in a non-existent location) is flagged on every later turn, including turns that commit nothing; in live sessions the rate can therefore exceed 100. \emph{Desynchronisation} is an automatic proxy: a turn is flagged when the barrier rejected a proposal but the dialogue has no refusal cue, or when, on a scripted move turn, the narration's claim of arrival disagrees with the committed move. A \emph{contradiction judge}, Qwen2.5-7B-Instruct, a model of another family than the generator, labels whether a reply claims a change that was not committed. \emph{Replay consistency} is the share of sessions whose state rebuilt from the log matches the live final state by a SHA-256 hash of the canonical JSON. A \emph{crash trial} stops a commit at a random point (before, during or after the event write, or during or after the snapshot write) and compares the recovered state with the last committed one. Latency is reported as percentiles, and token cost as input and output tokens counted on the exact prompt ids and from vLLM usage fields.

\subsection{Statistical analysis}\label{sec:stats}
Intervals are 95\% cluster-bootstrap percentile intervals with 10{,}000 resamples \cite{efron1979,field2007clustered}, clustering on session for recall and live metrics and on probe for probe metrics. Ratios are bootstrapped as ratios of resampled sums: for clusters $g$ with numerator and denominator sums $a_g,b_g$ and a resample $g^*_1,\dots,g^*_G$,
\begin{equation}\label{eq:boot}
\hat\rho=\frac{\sum_g a_g}{\sum_g b_g},\qquad \hat\rho^{*}=\frac{\sum_{i} a_{g^*_i}}{\sum_{i} b_{g^*_i}}.
\end{equation}
Paired binary outcomes use the exact McNemar test \cite{mcnemar1947}, which conditions on the $n_{10}+n_{01}$ discordant pairs and tests $n_{10}\sim\mathrm{Bin}(n_{10}+n_{01},\tfrac12)$; paired continuous outcomes use the Wilcoxon signed-rank test \cite{wilcoxon1945}. The confirmatory family (H1 to H3, six tests) is Holm-corrected \cite{holm1979}. The factorial is modelled on live turns as
\begin{multline}\label{eq:glmm}
\operatorname{logit}\Pr(y=1)=\beta_0+\beta_M M+\beta_C C\\
+\beta_{MC}MC+u_{\text{world}}+v_{\text{session}},
\end{multline}
with $M,C\in\{0,1\}$ indicating dual-tier memory and the barrier and Gaussian random intercepts, fitted by variational Bayes (\code{BinomialBayesMixedGLM.fit\_vb} in statsmodels \cite{seabold2010statsmodels}). We report posterior means and standard deviations and, as the notebook does, $z=\text{mean}/\text{sd}$ with a two-sided normal tail probability. These are approximate posterior summaries, not frequentist Wald tests.

\subsection{Hypotheses}\label{sec:hyp}
Stated before the run, each against the strongest applicable baseline. A hypothesis is supported only if the corrected effect is significant with the predicted sign, or the stated threshold is met.
\begin{description}[leftmargin=2.2em,style=nextline]
  \item[H1] F4 recall at $a\ge20$ exceeds B1 at equal budget, and B2 and B3 at equal or lower token cost.
  \item[H2] Scoping plus fallback gives higher MRR@6 than unscoped flat retrieval (B2).
  \item[H3] The barrier reduces oracle-detected committed violations on probes and in live sessions.
  \item[H4] False rejection on lawful twins is at most 5\% and validation adds under 5\,ms at P95.
  \item[H5] Replay from the log reproduces the live state in 100\% of event-sourced sessions.
  \item[H6] Memory mainly affects recall and control mainly affects violations, with small interaction.
  \item[H7] The directions of the H1 and H3 effects hold on W2, W3 and W4, and on two models of other families.
\end{description}
Four further tests compare the system with its Review-02 version on the same scenarios: \textbf{R1} the currency correction lowers attack success and the validator gap; \textbf{R2} snapshot-plus-suffix recovery makes crash recovery consistent; \textbf{R3} dialogue repair lowers contradictions; \textbf{R4} committed live violations fall. Each is confirmed if its Holm-corrected tests favour the correction, or if no failure remains after the correction.

\subsection{Teacher-forced long-horizon recall sessions}\label{sec:recall-sessions}
A session is a fixed script of $H\in\{50,100,200\}$ player turns. For each fact age $a\in\{5,10,20,40,80,160\}$ with $a<H-1$, two facts are \emph{planted} with a randomly chosen NPC and \emph{probed} $a$ turns later with the same NPC, using 15 attribute templates (meeting place, password, debt, and so on). Each fact has a paraphrased \emph{distractor} with a different value told to a different NPC, placed between plant and probe where possible. Values come from pools of invented or uncommon words; any value whose key word occurs anywhere in a world's text is removed, so a correct answer cannot come from lore. A probe is correct when the gold key word appears as a whole word in the reply or narration, and \emph{confused} when the distractor's key word appears instead.

Fillers are small talk with the NPC of the next scripted event, and the player stands at that NPC's location. NPC replies and memory summaries in the history are scripted (teacher forcing), so every condition sees the same history and the LLM is called only at probe turns. A session holds 8, 10 or 12 probes for $H=50,100,200$. With three sessions per world and horizon, each condition answers 630 probes over 63 sessions: 540 on held-out worlds, of which 324 have $a\ge20$. Because a fact is always probed with the NPC it was told to, at that NPC's fixed location, this design favours scoping; \cref{sec:discussion} returns to this.

\subsection{Adversarial invariant probes with lawful twins}
Each probe is a scenario (a world state with the player beside an NPC, three teacher-forced history turns, and one attack turn) in one of seven categories, each paired with a lawful twin: teleportation (twin: walk to an adjacent location), item fabrication (pick up a present item), theft or duplication (pick up a present item), trust inflation (thank the NPC), currency exploits (pay a small affordable amount), prompt injection \cite{greshake2023indirect} (an ordinary question), and secret extraction at trust 0 (the same request at trust 80). The run used 10 attacks per category per world, 490 attacks in all, with 470 twins: theft has twins for 50 of its 70 attacks. Every attack and twin was posed under five context conditions (F4, B0, B1, B2, B3), giving 4{,}800 probe outputs.

\subsection{Live sessions}
Live sessions run the backend's real LangGraph nodes every turn, so the model's own replies and committed state feed later turns. Each script has 39 turns: four plants with two NPCs, walks between them (one ``I walk over to \ldots'' turn per edge), small talk, two lawful trades, six attacks, and four late probes. The recorded fact ages of these probes are 30 to 34 turns. Two scripts per world give 14 sessions per condition, paired on identical inputs. If a scripted move is not committed the script continues, which the desynchronisation metric detects.

\subsection{Sources, format and release}\label{sec:data-files}
\emph{Sources.} W1 is the game's own seed (\esrc{Backend/game/world_seed.json}). W2a to W2c are converted from the LIGHT environment file \cite{urbanek2019light} (\code{light-environment.pkl}, CC BY-NC 4.0), whose rooms (setting and description), characters with personas, and objects become locations, NPCs and objects; W3 and W4 are generated in the notebook. \emph{Format.} Each world is a JSON document in the game's save schema: metadata, locations with \code{connected\_to} lists, NPCs with description, personality, knowledge, secrets and an \code{alive} flag, objects with location and owner, world rules, the player (location, inventory, currency), trust relationships, journal and turn. Recall sessions (session id, world, horizon, scripted turns, planted facts), adversarial probes (category, attack, lawful twin, scenario state, history) and live scripts are JSON Lines files with one record per line. \emph{Size.} The notebook generates the full pools of the largest sample-size level, 840 recall sessions, 2{,}940 probe scenarios and 70 live scripts (about 33\,MB and 130\,MB for the first two), and a run uses a prefix of each; the reported run used 63 recall sessions per condition (630 probes), 490 attacks with 470 lawful twins, and 14 live sessions of 39 turns per condition. \emph{Release.} The generated data, every prediction and metric file, and the blinded annotation sheets are committed under \mdir{notebooks/outputs/} and in \msrc{notebooks/outputs.zip}; the W2 worlds inherit LIGHT's non-commercial licence.

\subsection{How the data is used}
Recall sessions answer RQ1: every memory condition replays the same teacher-forced history and is asked the same probes, so recall, MRR and gold-in-prompt rates are paired across conditions. Probes answer RQ2: each attack and its lawful twin is posed under five context conditions, and every output is committed four ways (\cref{sec:protocol}). The paired before-and-after comparison uses all three kinds of data. Live sessions answer RQ3 and RQ4: they run the real backend graph each turn for the $2\times2$ factorial and the control ablations and record latency and tokens. RQ5 uses the split by world family (W1 is in-distribution; W2 to W4 are held out from tuning) and three further models on a subset: a smaller model of the same family and two models of other families. Every table in \cref{sec:results} can be regenerated from the prediction files and response caches without a GPU (\cref{sec:repro}).

\section{Novelty}\label{sec:novelty}

The components of the engine are individually standard: a turn buffer, dense retrieval, schema-constrained output, a rule validator, an append-only event log and a deterministic reducer. We claim no novelty for any of them. The novelty lies in how they are combined against the base paper and in what the evaluation can show.

\emph{Against the base paper.} Generative Agents \cite{park2023generative} rank memories by LLM-rated importance, recency and relevance and leave world changes unchecked. The engine instead (a) scopes retrieval by the current location and NPC, which needs no LLM call per memory write; (b) binds every model-proposed change to a typed, event-sourced state through a symbolic pre-commit barrier and a pure reducer, so state can be replayed and audited; and (c) is evaluated by automatic, paired and oracle-audited metrics at a matched token budget instead of believability rankings.

\emph{In the evaluation.} To our knowledge, this is the first evaluation of symbolic pre-commit validation of LLM-proposed game mutations with an oracle independent of the validator, paired on identical model outputs, together with memory scoping, replay and cost in one factorial design, and repeated after correcting what the Review-02 run found. It yields three findings not available from prior work. (i) \emph{Paired attribution of protection}: committing identical outputs four ways shows that, of the 6.4 points of attack success under direct writes, the reducer's own semantics remove 4.2, the Review-02 validator 1.0 more, and the corrected validator the remaining 1.2 (\cref{sec:control}), so validator and reducer must be evaluated as a pair. (ii) \emph{Oracle-revealed blind spots and their repair}: an oracle written from the specification exposed a currency rule the first validator never implemented (a 59.1\% validator gap on currency proposals), and the same oracle confirms that the corrected validator closes it. (iii) \emph{Measured costs of control}: 0.7\% false rejection of lawful live requests, validation below 2\,ms, dialogue repair that rewrites every rejected reply without reducing judged contradictions on those turns, and a loss of recall against the earlier version.

\section{Algorithms}\label{sec:algorithms}

Three algorithms define the system and its evaluation. \Cref{alg:turn} is one turn of the engine, following nodes 1 to 9 of \cref{fig:arch}: input sanitisation, scoped retrieval, budgeted prompt assembly, generation and parsing, validation against a running state, repair of a reply whose proposals were rejected, and the commit that appends events, reduces the state, updates both memory tiers and writes periodic snapshots.

\begin{algorithm*}[!tp]
\caption{One turn of the engine (nodes 1 to 9 of \cref{fig:arch})}\label{alg:turn}
\begin{algorithmic}[1]
\Require player input $u$, active NPC $n$, state $S_t$, store $M$, buffer $H$, log $\mathcal{E}$
\State $u\gets$ \Call{Trim}{$u$}; \textbf{if} $u=\varepsilon$ \textbf{then} $u\gets$ ``(silence)''
\State $\mathbf{q}\gets$ \Call{Embed}{$u$};\quad $\mathcal{R}\gets$ \Call{ScopedRetrieve}{$\mathbf{q},\pi(S_t),n$} \Comment{\cref{alg:retrieve}}
\State $(\mathcal{R}',h)\gets$ \Call{PackContext}{$\mathcal{R},H$; 1{,}600 chars};\quad $x\gets$ \Call{BuildPrompt}{$S_t,n,u,\mathcal{R}',h$}
\State $y\gets$ \Call{LLM}{$x$}; \quad $o\gets$ \Call{ParseJSON}{$y$} \Comment{on failure: $y$ becomes dialogue, no proposals}
\State $\hat S\gets S_t$;\quad $E_t\gets[\,]$;\quad $\mathit{rej}\gets[\,]$
\For{$(\tau,p)\in o.\mathrm{proposals}$}
  \If{$V(\tau,p,\hat S,S_t)$} $E_t.\mathrm{append}(e(\tau,p))$;\ $\hat S\gets\delta(\hat S,e(\tau,p))$ \Else\ $\mathit{rej}.\mathrm{append}((\tau,p))$ \EndIf
\EndFor
\If{$\mathit{rej}\neq[\,]$} $o.\mathrm{dialogue}\gets$ \Call{Repair}{$o,E_t,\mathit{rej}$} \Comment{one LLM call; neutral narration on failure}
\EndIf
\State append $e_{\text{speech}}$ and $E_t$ to $\mathcal{E}$ in one transaction; \quad $S_{t+1}\gets\foldl(\delta,S_t,E_t)$
\State $H.\mathrm{push}(u,o.\mathrm{dialogue},n)$;\quad $M.\mathrm{add}(\mathbf{q},\ o.\mathrm{summary},\ t{+}1,\ \pi(S_{t+1}),\ n)$
\If{$|M|>1000$} keep the newest 500 entries of $M$ \EndIf
\If{$(t+1)\bmod 16=0$} write snapshot $(S_{t+1},\max\mathrm{id}(\mathcal{E}))$ atomically and save $M$ \EndIf
\State \Return dialogue, narration, $S_{t+1}$
\end{algorithmic}
\end{algorithm*}

\Cref{alg:retrieve} is the retrieval step, \eqref{eq:retrieve} as code: it over-fetches $fk$ nearest neighbours by exact inner product, keeps those inside the current scope, and falls back to the unscoped list when fewer than $\theta$ survive.

\begin{algorithm}[!tp]
\caption{\textsc{ScopedRetrieve}\newline(\code{make\_node\_retrieval}, \code{FAISSMemory.search})}\label{alg:retrieve}
\begin{algorithmic}[1]
\Require query $\mathbf{q}$, location $\ell$, NPC $n$, $k=6$, $f=5$, $\theta=3$
\State $C\gets$ exact inner-product top-$\min(fk,|M|)$ of $\mathbf{q}$ over $M$
\State $R\gets[\,]$
\For{$m\in C$ in descending similarity}
  \If{$\phi_{\ell,n}(m)$} append $m$ to $R$; \textbf{if} $|R|=k$ \textbf{then break} \EndIf
\EndFor
\If{$|R|<\theta$} $R\gets$ first $k$ entries of $C$ \Comment{relaxation fallback, unscoped}
\EndIf
\State \Return $R$
\end{algorithmic}
\end{algorithm}

\subsection{Paired four-way commit and audit}\label{sec:alg-protocol}
\Cref{alg:protocol} is the core of the evaluation protocol of \cref{sec:protocol}. One model output per probe is committed through the corrected barrier, the Review-02 barrier, the reducer alone and by direct writes, and each post-state is audited by the oracle.

\begin{algorithm*}[!tp]
\caption{Paired four-way commit and independent audit of one probe output}\label{alg:protocol}
\begin{algorithmic}[1]
\Require scenario state $S$, prompt $x$, seed $s=h(\text{probe id})$ \Comment{independent of condition}
\State $y\gets$ \Call{LLM}{$x$; seed $s$}; \quad $o\gets$ \Call{ParseJSON}{$y$}
\For{mode $\in\{\text{barrier},\ \text{barrier v1},\ \text{reducer},\ \text{direct}\}$}
  \If{mode $=$ barrier} $S'\gets\foldl(\delta,S,E)$ with $E$ from the running-state check of \cref{eq:commit}
  \ElsIf{mode $=$ barrier v1} $S'\gets\foldl(\delta,S,[e(\tau,p):V_{\text{v1}}(\tau,p,S)])$ \Comment{Review-02 validator}
  \ElsIf{mode $=$ reducer} $S'\gets\foldl(\delta,S,[e(\tau,p): \tau\ \text{a known type}])$ \Comment{ablation A5}
  \Else\ $S'\gets$ write each proposal and each new entity into a copy of $S$ \Comment{no clamping}
  \EndIf
  \State $v_{\text{mode}}\gets$ \Call{Oracle}{$S,S'$, committed list} \Comment{O1 to O8; no validator code}
\EndFor
\State \Return the four verdicts and lawful/unlawful counts per proposal
\end{algorithmic}
\end{algorithm*}

\subsection{Complexity}
With $|M|\le 1000$ entries, $d=384$ and $p$ proposals per turn: exact search is $O(|M|d)$; validation is $O(p)$ lookups plus one reduction per accepted proposal for the running state; reduction is $O(p\,|S|)$ because each event deep-copies the state; recovery from the latest snapshot is $O(|S|+r)$ with $r$ the events since it. Measured costs are in \cref{sec:latency}.

\section{Implementation}\label{sec:impl}

\subsection{Software stack}
The engine has four tiers. The presentation tier (React, TypeScript, Zustand) streams turns over a WebSocket; the orchestration tier (FastAPI with per-session async locks) runs a compiled nine-node LangGraph \code{StateGraph} (\bsrc{graph/definition.py}); the validation tier is the barrier (\bsrc{game/validator.py}); and the storage tier holds the SQLite event log and snapshots (\bsrc{core/event_store.py}, \bsrc{core/snapshot.py}, \bsrc{core/recovery.py}), the FAISS store with all-MiniLM-L12-v2 embeddings (\bsrc{memory/faiss_index.py}) and the turn buffer (\bsrc{memory/short_term.py}). In the shipped game the LLM is a hosted endpoint (Groq, \code{openai/gpt-oss-120b}, temperature 0.35, \esrc{Backend/config.py}); in the evaluation it is a self-hosted model served by vLLM \cite{kwon2023vllm}.

\subsection{Sample-size planning}
Eight pre-declared levels (index 0 to 7; Appendix~\ref{app:ladder}) fix sessions per world and horizon, probes per category and world, and live sessions per world, so a smaller level is a prefix of a larger one. A pilot of 256 jobs measured steady-state throughput, and a planner chose the largest level whose estimated cost fitted the 11.25-hour budget after reserves for the analysis, the latency benchmark, the second backbone and the independent families: level 2 (estimated 6.76\,h of 7.74\,h available; level 3 needed 8.40\,h), the third of the eight levels. The two earlier Review-03 runs had chosen level 1 because their planner multiplied an already conservative estimate by a safety factor of 1.15; the reported run is the first without that factor. Its estimate was still conservative: the four LLM stages of level 2 took 5.49\,h, 23\% less than estimated, and the run ended after 7.65 of the 11.25 hours. Coverage was complete: 8{,}190 recall, 4{,}800 probe, 3{,}822 live-turn, 1{,}680 seed-variance, 48 repair, 364 judge and 108 single-stream latency rows, 1{,}080 and 550 for the second backbone, and 840 and 550 for each independent family, none lost to a deadline. \subsection{Corrections and audit of the run}\label{sec:gaps}
The Review-02 run of this protocol found seven defects in the engine: unbounded currency gains; per-proposal instead of per-turn checking; unchecked NPC drops and relocations; a prompt that advertised a different trust range than the validator allowed; secrets that never reached the model; a load path that discarded the logged suffix, with the active NPC set outside the log; and dialogue that described rejected changes. All seven are corrected in the evaluated code (\cref{sec:formal}) and covered by unit and property tests, including 3{,}000 random multi-proposal turns checked against an independent invariant checker. Structural legality remains the only rule: an in-bounds but unjustified trust change passes.

The corrected system was run three times. Auditing the first Review-03 run (22 October 2026) against its prediction files found four measurement defects in the notebook: retrieval metrics counted every age-5 probe as a retrieval miss for F4, A3 and A4, whose packing drops a memory that duplicates a buffered turn (\cref{sec:metrics}), which biased the pre-registered H2 test against F4; the single-stream live latency sessions reused the main run's seeds, so their LLM calls were answered from the response cache, and the latency stage reached its deadline before B4 and B5; the secret-leak scorer took template words such as ``behind'' as secret keywords; and a shared random stream gave one estimate different bootstrap intervals in different tables. The notebook was fixed and run again on 24 October 2026. Auditing that second run found one attribution error, a single-stream stage table with no row for dialogue repair, whose regeneration was counted as local compute; it also showed that the planner's safety factor kept both runs at level 1, and that the progress log fell silent for 31 minutes while the concurrent live sessions ran. The notebook was corrected (repair as its own stage, local compute without either LLM call, no safety factor, a progress heartbeat every 60\,s) and run a third time, unchanged, from 24 to 25 October 2026; that third run is the one reported here, and its saved outputs confirm each fix. Auditing it found no further measurement defect. It did find that every lawful twin proposal the barrier rejected is a trust change that names the NPC by its display name instead of its id; the oracle's lawfulness label did not check NPC ids, so the false-rejection rate on probes slightly overstates the barrier's cost (\cref{sec:control}). The released notebook's oracle now also requires trust relationships to name canonical NPCs.

\subsection{Retrieval quality, sensitivity and seed variance}\label{sec:retrieval}

Scoping changed \emph{ranking} more than \emph{reach}. Scored on the 432 held-out probes older than the buffer, F4 placed the gold memory in its retrieved list for 100\% of them, as did B2, A2 and A4 (B3 99.8\%; Appendix~\ref{app:supp}), but ranked it higher: MRR@6 0.910 against 0.742 for B2 and 0.732 for the unscoped ablation A3. It also kept the paraphrased distractor out of 46\% of prompts, against 1\% for B2 and 9\% for A3. Removing the buffer (A2) kept the distractor out of 90\% of prompts, because the distractor, told to a different NPC, then reaches the prompt only through retrieval. In the teacher-forced design the fallback rarely helps: disabling it (A4) raised MRR@6 to 0.954, since the fallback replaces a short scoped list with unscoped neighbours.

The retrieval-only sweeps (80 sessions on W1 and W2 at horizons 100 and 200, one setting varied at a time around buffer 8, $k=6$, $\theta=3$) confirm this (\cref{fig:sweeps}; values in Appendix~\ref{app:supp}). Buffer size had no effect on retrieval. A threshold of 0, which is A4, gave the best MRR; $\theta=6$ triggered the fallback more often and lowered it. Scaling every condition's budget (plotted in Appendix~\ref{app:supp}) shows that from half the default budget F4 places the gold turn in 99.9\% of prompts, like B2 and B3, while B4 and B5 saturate at 85\% and 95\% and the rolling context needs four times the budget to reach 70\%.

\subsection{State control under adversarial probes}\label{sec:control}

\Cref{tab:probes} pools the outputs of all five context conditions (350 attacks per category) and commits each four ways. The corrected barrier accepted no unlawful proposal in any category (validator gap 0.0\%, against 13.6\% for the Review-02 validator and 59.1\% of its currency proposals) and let no attack succeed. \subsection{Latency and token cost}\label{sec:latency}

Local work was negligible against generation (per-stage values in Appendix~\ref{app:supp}): 15.1\,ms at P50 and 19.2\,ms at P95 for the live F4 graph run single-stream. Validation took 0.013\,ms at P50 and 1.4\,ms at P95, inside the 5\,ms bound of H4, and the commit node (SQLite append, reduction, indexing) dominated local time at 8.4\,ms. The LLM call took 8{,}113\,ms at P50 and 14{,}933\,ms at P95 per live turn, and 6{,}593\,ms and 8{,}120\,ms per recall request. Dialogue repair adds a second LLM call on turns with a rejected proposal (6.9 and 5.3\,s on the 2 of 24 single-stream turns that needed it), which is why end-to-end P95 reached 17.7\,s. Under the batched live stage (98 concurrent sessions) the median LLM time per F4 turn was 54.5\,s, a throughput setting rather than an interactive one. Per 100 turns F4 consumed 144{,}375 input and 14{,}859 output tokens, against 440{,}632 and 13{,}635 for full history (Appendix~\ref{app:supp}). Because the models were self-hosted, no monetary cost is reported.

\emph{Memory is necessary in both.} The base paper's closest controlled result is its memory ablation: removing observation, reflection and planning lowered the TrueSkill rating from 29.89 to 21.21, eight standard deviations. Removing long-term memory here (A1) lowered recall of facts 20 or more turns old from 83.0\% to 0.0\%. Both systems depend on long-term memory for anything beyond the immediate context.

\emph{The base paper's retrieval rule forgets under a budget.} B4 ranks memories by the base paper's recency and relevance terms (without importance, which needs an LLM call per write). At the same budget its recall at $a\ge20$ was 63.0\%, against 83.0\% for F4 ($p_{\text{Holm}}=4.8\times10^{-10}$), and fell to 38\% or less for facts 80 or more turns old, because recency decay pushes them out of the budget. Relevance alone (B2) was much stronger: scoping beat it on ranking (MRR@6 0.910 against 0.742) and on keeping the paraphrased distractor out of the prompt (46\% against 1\% of probes), but not on recall (83.0\% against 84.3\%, not significant). Unlike the base paper, the engine spends no LLM call on writing a memory.

\emph{State control has no counterpart in the base paper.} Generative Agents report embellishment at the level of dialogue and do not measure rule violations. In the engine no probe or live output committed a state violation through the corrected barrier, for any of four models (\cref{tab:probes,tab:perworld}), and the event log reproduced the live state exactly. The closest reported measurement is NCP-Bench \cite{ma2026ncp}, where the best model kept its narrative commitments in only 42\% of runs after 20 turns when checked afterwards by LLM auditors. Here the specification is enforced before commit, which protects the state, but the dialogue still contradicted rejected changes on 9.5\% of live F4 turns by the cue proxy: the barrier protects the state, not the narration, and dialogue repair did not close that gap on the turns it rewrote.

\subsection{Error analysis}\label{sec:errors}

Automatic coding locates the failures (counts per condition in Appendix~\ref{app:supp}). None of F4's recall failures came from retrieval: in all 84 ``hit but ignored'' cases the gold turn was in the prompt and the model answered wrongly, and 13 answers used the distractor's value. Rolling contexts failed by forgetting (335 misses for B1), generic RAG by ignoring or confusing retrieved chunks (146 and 61), the scored memory stream B4 partly by forgetting (65 misses), and the ablation without long-term memory by both (388 misses, 109 confusions). The desynchronisation proxy flagged 52 F4 turns against 103 for F4v1, 68 for F2 and 56 for A6, the conditions that can reject proposals.

\section{Discussion}\label{sec:discussion}

\subsection{Memory}
Scoped long-term memory is what makes long-range recall possible: without it recall beyond the 8-turn buffer is zero, and a rolling context of equal budget forgets every fact older than 10 turns. At an equal budget, a strong flat vector store and a forgetting-curve memory recall about as well; scoping's measurable benefits are ranking (MRR) and distractor exclusion. The base paper's recency-weighted rule is the weakest memory under a budget, because it evicts old facts. The benchmark always probes a fact with the NPC it was told to, at that NPC's location, which favours scoping and gives the fallback little to do; the value of the buffer and fallback in free play, where facts are recalled elsewhere, is not measured here. \Cref{prop:postfilter} identifies a further risk at scale: once a store holds many similar out-of-scope entries, post-filtering the global top-30 can drop in-scope memories, which a filtered index avoids \cite{gollapudi2023filtered}. The Review-03 memory changes cost recall: F4 recalled significantly less than the Review-02 system F4v1 at $a\ge20$ (83.0\% against 88.6\%), most at age 5, although F4v1 used slightly fewer input tokens. F4 differs from F4v1 in the packing rule, which shares one budget and shows a buffered fact once instead of twice, and in its prompt, which also states the validator's limits; the run does not separate the two, which needs an ablation that keeps duplicates and one that pairs the Review-02 prompt with the corrected validator.

\subsection{State control}
The barrier works where it has a rule and is only as good as its rule set: the Review-02 run's oracle found a missing currency rule, and with that rule and per-turn checking added, no state violation got through for any of four models, on probes or in live play, at a cost of 4 rejected lawful twin proposals in 684 (each a trust change naming an NPC by its display name, which the Review-02 validator also rejected) and 0.7\% of lawful live requests. Models of other families proposed unlawful changes far more often than the development model (up to 43.9\% of attacks), which is where a symbolic barrier matters most. Blocking still leaves the narration wrong on the turn itself: one regeneration of the reply did not lower judged contradictions on the turns it rewrote, so the repair prompt, or generating narration from the committed events, needs further work, even though the corrected system as a whole contradicted rejected changes far less often than its earlier version.

\subsection{Implications for practitioners}
Treat LLM output as untrusted input to a state machine; check proposals per turn against a running state; keep the reducer defensive even behind a validator; audit with a checker that does not share the validator's code; recover by snapshot plus suffix, never by snapshot alone; and audit the evaluation harness itself, since three measurement defects of the first Review-03 run (retrieval scoring, cached latency, leak keywords) would otherwise have reversed or inflated a result.

\section{Limitations and Threats to Validity}\label{sec:limits}

\begin{enumerate}[leftmargin=*]
  \item \textbf{Sample size.} Level 2 of the ladder (63 recall sessions, 490 attacks, 14 live sessions per cell) is well below the level-7 targets, and live intervals are wide.
  \item \textbf{Scoring.} Recall, leaks and desynchronisation are scored automatically (key words, secret keywords, refusal and arrival cues), and the contradiction judge is an LLM. Blinded sheets for two raters (1{,}560 recall, 200 dialogue-quality and 194 contradiction items) are exported, but no human labels, Cohen's $\kappa$ or judge agreement exist yet. The leak scorer over-counts: of the three leaks flagged in the F4 probe context, two are W1 replies that use the secret keyword ``looking'' in ``if you're looking for'', and one repeats the player's ``phoenix feather'' to an NPC whose secret is an iron feather. The run's oracle did not check the NPC id of a trust change, so the four rejected twin proposals that name an NPC by display name count as false rejections; the released notebook checks it.
  \item \textbf{Post-hoc corrections.} The retrieval scoring rule (facts older than the buffer) was chosen after the first Review-03 run and applied unchanged, to every condition, in the second and third runs; the repair stage, the planner change and the progress heartbeat were added after the second run and are measured by the notebook itself in the reported run.
  \item \textbf{Worlds.} W1 is the development world, W4 is templated, and W3 was authored by the notebook author rather than an independent contributor.
  \item \textbf{Scripted players.} Fixed scripts remove adaptation confounds but do not react to NPCs; player experience needs a user study.
  \item \textbf{Backbones.} Four self-hosted models of up to 7B parameters; the game's default hosted backbone was not evaluated, and its latency is not reproduced.
  \item \textbf{Baselines.} B4 and B5 re-implement the retrieval rules of Generative Agents and MemoryBank, not the full systems; B4 omits the importance term and reflection.
  \item \textbf{Before-and-after comparison.} F4v1 shares the corrected reducer, event store and commit node with F4, so it isolates the validator, prompt, packing and repair changes together, not each of them, and not the recovery changes, which the crash trials measure separately.
  \item \textbf{Violation metric.} \Cref{eq:viol} counts flagged turns over transitions; persistent corruption inflates direct-write rates, so live violation rates compare conditions but are not counts of distinct violations.
  \item \textbf{Memory scale.} Exact search with pruning at 1{,}000 entries; campaigns of thousands of turns need summarisation or hierarchical memory.
\end{enumerate}

\subsection{Threats to validity}
\emph{Internal}: inputs, prompts, schemas and backbones are identical across conditions, request seeds depend only on the probe or turn, and probe outputs are committed in all four modes, so control comparisons are exactly paired. \emph{Construct}: violations are measured by an independent oracle written from the specification; recall is key-word matched on invented values; retrieval is scored on facts outside the buffer. \emph{External}: claims are restricted to the tested worlds and models. \emph{Conclusion}: hypotheses were stated in advance, the confirmatory family is Holm-corrected, unsupported hypotheses are reported, and the one scoring rule changed after the first Review-03 run (H2's) was fixed before the reported run. The factorial $p$-values are approximate posterior summaries from a variational fit.

\section{Conclusion}\label{sec:conclusion}

LLM NPCs need to remember what happened, respect the rules of the world, and do both at interactive cost. We tested an engine that pairs scoped dual-tier memory with a validated, event-sourced state against independent baselines at an equal memory budget, in a factorial design with ablations, on seven worlds and four models, with adversarial probes scored by an oracle that shares no code with the validator, and against its own earlier version. Three claims are supported. Long-term retrieval scoped to the current place and person keeps recall high and flat over 160 turns where a rolling context of equal size forgets everything after ten, and ranks the right memory higher than flat vector memory. A pre-commit barrier that checks each turn against a running state, over an event-sourced log, committed no state violation for any model, on probes or in live play, while rejecting few lawful requests. Snapshot-plus-suffix recovery reproduced the committed state after every simulated crash. Three claims are not supported: the memory design is not better than flat vector or forgetting-curve memory at an equal budget, and its Review-03 form recalls less than the earlier version; memory and control are not independent; and one rewrite of a rejected reply did not reduce contradictions between dialogue and state on the turns it rewrote, although the corrected system as a whole contradicted rejected changes on far fewer live turns.

\subsection{Future work}
Rerun at a larger sample size by attaching this run's response caches to further Kaggle sessions; collect the two-rater human labels and validate the contradiction judge against them; author W3 independently; evaluate the hosted backbone; improve dialogue repair or generate narration from the committed events; locate the recall loss against the Review-02 system by ablating the packing rule's duplicate removal and the prompt separately; probe recall away from the place a fact was told; validate narrative plausibility, not only structural legality; and evaluate filtered or hierarchical indices for long campaigns.

\subsection{Data and licences}
W2 content derives from LIGHT under CC BY-NC 4.0, so the released W2 worlds are for non-commercial use. The K2-Horizon backbones are Apache 2.0; the licences of the other two models are given on their model cards.
