\section{Algorithms}\label{sec:algorithms-ext}

\Cref{alg:turn} is one turn of the engine, following nodes 1 to 9 of \cref{M-fig:arch}: input sanitisation, scoped retrieval, budgeted prompt assembly, generation and parsing, validation against a running state, repair of a reply whose proposals were rejected, and the commit that appends events, reduces the state, updates both memory tiers and writes periodic snapshots.

\begin{algorithm}[H]
\caption{One turn of the engine}\label{alg:turn}
\begin{algorithmic}[1]
\Require player input $u$, active NPC $n$, state $S_t$, store $M$, buffer $H$, log $\mathcal{E}$
\State $u\gets$ \Call{Trim}{$u$}, \textbf{if} $u=\varepsilon$ \textbf{then} $u\gets$ ``(silence)''
\State $\mathbf{q}\gets$ \Call{Embed}{$u$},\quad $\mathcal{R}\gets$ \Call{ScopedRetrieve}{$\mathbf{q},\pi(S_t),n$} \Comment{\cref{alg:retrieve}}
\State $(\mathcal{R}',h)\gets$ \Call{PackContext}{$\mathcal{R},H$, 1{,}600 chars},\quad $x\gets$ \Call{BuildPrompt}{$S_t,n,u,\mathcal{R}',h$}
\State $y\gets$ \Call{LLM}{$x$}, \quad $o\gets$ \Call{ParseJSON}{$y$} \Comment{on failure: $y$ becomes dialogue, no proposals}
\State $\hat S\gets S_t$,\quad $E_t\gets[\,]$,\quad $\mathit{rej}\gets[\,]$
\For{$(\tau,p)\in o.\mathrm{proposals}$}
  \If{$V(\tau,p,\hat S,S_t)$} $E_t.\mathrm{append}(e(\tau,p))$,\ $\hat S\gets\delta(\hat S,e(\tau,p))$ \Else\ $\mathit{rej}.\mathrm{append}((\tau,p))$ \EndIf
\EndFor
\If{$\mathit{rej}\neq[\,]$} $o.\mathrm{dialogue}\gets$ \Call{Repair}{$o,E_t,\mathit{rej}$} \Comment{one LLM call, neutral narration on failure}
\EndIf
\State append $e_{\text{speech}}$ and $E_t$ to $\mathcal{E}$ in one transaction, \quad $S_{t+1}\gets\foldl(\delta,S_t,E_t)$
\State $H.\mathrm{push}(u,o.\mathrm{dialogue},n)$,\quad $M.\mathrm{add}(\mathbf{q},\ o.\mathrm{summary},\ t{+}1,\ \pi(S_{t+1}),\ n)$
\If{$|M|>1000$} keep the newest 500 entries of $M$ \EndIf
\If{$(t+1)\bmod 16=0$} write snapshot $(S_{t+1},\max\mathrm{id}(\mathcal{E}))$ atomically and save $M$ \EndIf
\State \Return dialogue, narration, $S_{t+1}$
\end{algorithmic}
\end{algorithm}

\Cref{alg:retrieve} is the retrieval step, \eqref{M-eq:retrieve} as code (\code{make\_node\_retrieval} and \code{FAISSMemory.search} in the backend): it over-fetches $fk$ nearest neighbours by exact inner product, keeps those inside the current scope, and falls back to the unscoped list when fewer than $\theta$ survive.

\begin{algorithm}[H]
\caption{Scoped retrieval}\label{alg:retrieve}
\begin{algorithmic}[1]
\Require query $\mathbf{q}$, location $\ell$, NPC $n$, $k=6$, $f=5$, $\theta=3$
\State $C\gets$ exact inner-product top-$\min(fk,|M|)$ of $\mathbf{q}$ over $M$
\State $R\gets[\,]$
\For{$m\in C$ in descending similarity}
  \If{$\phi_{\ell,n}(m)$} append $m$ to $R$, \textbf{if} $|R|=k$ \textbf{then break} \EndIf
\EndFor
\If{$|R|<\theta$} $R\gets$ first $k$ entries of $C$ \Comment{relaxation fallback, unscoped}
\EndIf
\State \Return $R$
\end{algorithmic}
\end{algorithm}


\subsection{Paired five-way commit and audit}\label{sec:alg-protocol}
\Cref{alg:protocol} is the core of the evaluation protocol of \cref{M-sec:protocol}. Each probe yields one model output, which is committed in five ways (corrected barrier, corrected barrier after canonicalisation, Review-02 barrier, reducer without a validator, direct writes), and the oracle then audits every resulting state.

\begin{algorithm}[H]
\caption{Paired five-way commit and audit of one probe output}\label{alg:protocol}
\begin{algorithmic}[1]
\Require scenario state $S$, prompt $x$, seed $s=h(\text{probe id})$ \Comment{independent of condition}
\State $y\gets$ \Call{LLM}{$x$, seed $s$}, \quad $o\gets$ \Call{ParseJSON}{$y$}
\For{mode $\in\{\text{barrier},\ \text{barrier canon},\ \text{barrier v1},\ \text{reducer},\ \text{direct}\}$}
  \If{mode $=$ barrier} $S'\gets\foldl(\delta,S,E)$ with $E$ from the running-state check of \cref{M-eq:commit}
  \ElsIf{mode $=$ barrier canon} as barrier, after mapping exact display names and slugs to ids \Comment{offline candidate}
  \ElsIf{mode $=$ barrier v1} $S'\gets\foldl(\delta,S,[e(\tau,p):V_{\text{v1}}(\tau,p,S)])$ \Comment{Review-02 validator}
  \ElsIf{mode $=$ reducer} $S'\gets\foldl(\delta,S,[e(\tau,p): \tau\ \text{a known type}])$ \Comment{ablation A5}
  \Else\ $S'\gets$ write each proposal and each new entity into a copy of $S$ \Comment{no clamping}
  \EndIf
  \State $v_{\text{mode}}\gets$ \Call{Oracle}{$S,S'$, committed list} \Comment{O1 to O8, no validator code}
\EndFor
\State \Return the five verdicts and lawful/unlawful counts per proposal, as written and by intent
\end{algorithmic}
\end{algorithm}

\subsection{Complexity}
With $|M|\le 1000$ entries, $d=384$ and $p$ proposals per turn: exact search is $O(|M|d)$. Validation is $O(p)$ lookups plus one reduction per accepted proposal for the running state. Reduction is $O(p\,|S|)$ because each event deep-copies the state. Recovery from the latest snapshot is $O(|S|+r)$ with $r$ the events since it. Measured costs are in \cref{sec:latency}.

\section{Dataset Description and Usage}\label{sec:dataset-ext}

The dataset is a benchmark built for this study: seven worlds, teacher-forced recall sessions, adversarial probes with lawful twins, and live-session scripts, generated deterministically by the evaluation notebook from a master seed, together with the model outputs and metrics of the reported run. \Cref{sec:data-files} lists the released files and how each is used.

\subsection{World suite}
A single hand-made world cannot support generalisation claims, and a benchmark written by the system's authors risks being tuned to it. The suite therefore has four families (\cref{tab:worlds,fig:worlds}): W1, the in-house dark-fantasy development world (\esrc{Backend/game/world_seed.json}), and W2a to W2c, which a deterministic seeded script derives from the crowd-written LIGHT environment \cite{urbanek2019light} (\href{https://dl.fbaipublicfiles.com/parlai/light/light-environment.pkl}{\code{light-environment.pkl}}, licensed CC BY-NC 4.0), with LIGHT's fragmented room graph joined by a seeded spanning tree and two templated secrets per NPC built from words that occur nowhere else in the world. W3 is a 24-location science-fiction station authored in the notebook from a written specification before any system run, and W4-32 and W4-128 are procedurally generated: a random spanning tree receives roughly 30\% additional edges, and names are filled from templates. No system setting was tuned on W2 to W4. W3 is held out from tuning but was \emph{not} independently authored. \Cref{tab:worlds} lists the size of each world as built for the run (\osrc{metrics/world_stats.csv}), where the join column counts the spanning-tree edges added to connect LIGHT's room graph, and \cref{fig:worlds} plots the numbers of locations, NPCs and objects on a log scale. The procedural W4-128 extends the suite to 128 locations, 16 NPCs and 64 objects.

\subsection{Teacher-forced long-horizon recall sessions}\label{sec:recall-sessions}
A session is a fixed script of $H\in\{50,100,200\}$ player turns. For each fact age $a\in\{5,10,20,40,80,160\}$ with $a<H-1$, the script tells two facts to a randomly chosen NPC (the \emph{plant}) and asks the same NPC about them $a$ turns afterwards (the \emph{probe}), using 15 attribute templates (meeting place, password, debt, and so on), each attribute at most once per session. Each fact has a paraphrased \emph{distractor} with a different value told to a different NPC, placed between plant and probe where possible. A quarter of facts are \emph{knowledge updates}: the player first tells one value and corrects it at the gold turn. Half have a \emph{lure turn}, small talk about the same topic. Values are drawn from pools of made-up or rare words, and a value is discarded if its key word appears anywhere in the world's text, so lore alone cannot supply a correct answer. Under the strict rule a probe counts as correct if the output parses and the reply contains the gold key word as a whole word while mentioning neither the distractor's value nor a superseded value. A reply is \emph{confused} if it gives the distractor's value in place of the gold one, and \emph{hedged} if it gives the gold value together with a competing value.

Fillers are small talk with the NPC of the next scripted event, with varied scripted replies, and the player stands at that NPC's location. NPC replies and memory summaries in the history are scripted (teacher forcing), so every condition sees the same history and the LLM is called only at probe turns. The full pool holds 210 sessions and 2{,}092 facts, of which 23.7\% are knowledge updates and 48.4\% have a lure turn. With five sessions per world and horizon, each condition answers 1{,}045 probes over 105 sessions: 897 on held-out worlds, of which 537 have $a\ge20$. Because a fact is always probed with the NPC it was told to, at that NPC's fixed location, this design favours scoping. Knowledge updates and lure turns are the only probes where scoping cannot separate the gold memory from its competitors.

\subsection{Adversarial invariant probes with lawful twins}
Each probe is a scenario (a world state with the player beside an NPC, three teacher-forced history turns, and one attack turn) in one of seven categories, each paired with a lawful twin: teleportation (twin: walk to an adjacent location), item fabrication (pick up a present item), theft or duplication (pick up a present item), trust inflation (thank the NPC), currency exploits (pay a small affordable amount), prompt injection \cite{greshake2023indirect} (an ordinary question), and secret extraction at trust 0 (the same request at trust 80). Each category has six attack templates. The run used 22 attacks per category per world, 1{,}078 in all, with 1{,}027 twins: theft has twins for 103 of its 154 attacks. A probe prompt is the same under every memory condition, so every attack and twin was posed once, under F4's context, giving 2{,}105 probe outputs.

\subsection{Live sessions}
Live sessions run the backend's real LangGraph nodes every turn, so the model's own replies and committed state feed later turns. Each script has 39 turns: four plants with two NPCs, walks between them (one ``I walk over to \ldots'' turn per edge), small talk, two lawful trades, six attacks, and four late probes at fact ages of about 20 to 32 turns. Two scripts per world give 14 sessions per condition, paired on identical inputs. If the model fails to commit a scripted move, the engine performs it, which keeps every condition on the same trajectory, and the share of moves the model committed itself is reported on its own.

\subsection{Sources, format and release}\label{sec:data-files}
\emph{Sources.} W1 is the game's own seed (\esrc{Backend/game/world_seed.json}). W2a to W2c are converted from the LIGHT environment file \cite{urbanek2019light} (\code{light-environment.pkl}, CC BY-NC 4.0), whose rooms (setting and description), characters with personas, and objects become locations, NPCs and objects. W3 and W4 are generated in the notebook. \emph{Format.} Each world is a JSON document in the game's save schema: metadata, locations with \code{connected\_to} lists, NPCs with description, personality, knowledge, secrets and an \code{alive} flag, objects with location and owner, world rules, the player (location, inventory, currency), trust relationships, journal and turn. Recall sessions (session id, world, horizon, scripted turns, planted facts), adversarial probes (category, attack, lawful twin, scenario state, history) and live scripts are JSON Lines files with one record per line. \emph{Size.} The notebook generates the full pools of the largest sample-size level, 210 recall sessions, 1{,}960 probe scenarios and 35 live scripts (about 8\,MB, 87\,MB and 0.2\,MB), and a run uses a prefix of each. \emph{Release.} The generated data, every prediction and metric file, and the blinded annotation sheets are committed under \mdir{notebooks/outputs/} and in \msrc{notebooks/outputs.zip}. The W2 worlds inherit LIGHT's non-commercial licence.

\subsection{How the data is used}
Recall sessions answer RQ1: every memory condition replays the same teacher-forced history and is asked the same probes, so recall, MRR and gold-in-prompt rates are paired across conditions. Probes answer RQ2: each attack and its lawful twin is committed five ways (\cref{M-sec:protocol}), and the differential test (\cref{sec:differential}) adds random proposals. The paired before-and-after comparison uses all three kinds of data. Live sessions answer RQ3 and RQ4: they run the real backend graph each turn for the $2\times2$ factorial and the control ablations and record latency and tokens. RQ5 uses the split by world family (W1 is in-distribution, W2 to W4 are held out from tuning) and three further models on a subset: a smaller model of the same family and two models of other families. Every table in \cref{M-sec:results} can be regenerated from the prediction files and response caches without a GPU (\cref{sec:repro}).

\section{Implementation and Run}\label{sec:impl-ext}

\subsection{Software stack}
The engine has four tiers. The presentation tier (React, TypeScript, Zustand) streams turns over a WebSocket. The orchestration tier (FastAPI with per-session async locks) runs a compiled nine-node LangGraph \code{StateGraph} (\bsrc{graph/definition.py}). The validation tier is the barrier (\bsrc{game/validator.py}). The storage tier holds the SQLite event log and snapshots (\bsrc{core/event_store.py}, \bsrc{core/snapshot.py}, \bsrc{core/recovery.py}), the FAISS store with all-MiniLM-L12-v2 embeddings (\bsrc{memory/faiss_index.py}) and the turn buffer (\bsrc{memory/short_term.py}). In the shipped game the LLM is a hosted endpoint (Groq, \code{openai/gpt-oss-120b}, temperature 0.35, \esrc{Backend/config.py}). In the evaluation it is a self-hosted model served by vLLM \cite{kwon2023vllm}.

\subsection{System under test}\label{sec:repro}
The notebook \msrc{notebooks/npc-memory-state-benchmark.ipynb} does not clone the repository: it embeds the backend source of commit \commit{9b38dcfeb506b797c38a07a8bc357da707e34e7c} as a hashed bundle (SHA-256 \code{84a4c1ced397}\ldots, 45 files), and, for condition F4v1, the Review-02 validator and prompt builder from commit \commit{0ea345fe140b359d7e82e77ffb2fdfa74caf0e7c}, asserts the hash, and imports the real backend modules (reducer, validator, event store, snapshots, recovery, prompt builder and packing, FAISS memory, buffer, JSON extractor and the LangGraph node factories). Live conditions are built from the backend's own nodes, swapping only the nodes a condition changes. Code written for the evaluation is limited to the baselines, the oracle and the generators of the benchmark. Before any GPU time, a self-test with a deterministic mock LLM checks that the oracle flags direct writes, that the corrected barrier commits no more violations than the Review-02 barrier, that event-sourced sessions replay exactly, that the corrected load path recovers after a crash, and that the notebook's scoped retrieval matches \code{node\_retrieval}. \Cref{tab:config} lists the run configuration recorded in \osrc{metrics/run_manifest.json}.

\subsection{Sample-size planning}
Twelve levels, numbered 0 to 11 and declared in advance (\cref{app:ladder}), set how many recall sessions, probes and live sessions the run contains, and each step up enlarges a single costly dimension, so every level is a prefix of the next. A 256-job pilot measured throughput at steady state. A planner then picked the largest level whose estimated cost fitted the remaining time, after setting aside reserves for analysis, the latency benchmark, the second backbone and the two models of other families, which gave level 3 (7.28\,h estimated against 7.69\,h available). Once the required stages, the seed-variance stage and the latency benchmark had finished, the run grew the sample one level at a time, timing each step from its own measured rates. Level 4 needed 68.3 of a projected 90.9 minutes and level 5 needed 68.2 of 90.4. Level 6 would have needed about 46 minutes, but only 26 remained before the reserves, so the run stopped at level 5. The run ended after 9.66 of the 11.25 budgeted hours. Coverage was complete: 13{,}585 recall, 2{,}105 probe, 3{,}822 live-turn, 1{,}656 seed-variance, 117 repair, 329 judge, 1{,}258 adjudication and 96 single-stream latency rows, 960 and 770 for the second backbone, and 840 and 770 for each independent family, none lost to a deadline. The primary model server produced 24{,}216 responses, and a further 1{,}530 came from the response cache, either pilot responses that the main stages reused or prompts that several conditions had in common. \Cref{fig:gpu} shows the utilisation of both T4 GPUs over the 9.66-hour run, sampled by \code{nvidia-smi}. Both stay close to full load from the end of the pilot (0.5\,h) until the second extension level ends (8.3\,h). The brief dips mark changes of stage, and the last segment covers the second backbone and the two models of other families, with the server restarted between them.

\subsection{Execution procedure}
(1) Create a Kaggle notebook from \msrc{notebooks/npc-memory-state-benchmark.ipynb}, select \emph{GPU T4 x2}, enable Internet, and optionally attach an independently written \code{w3\_world\_seed.json} or completed rating sheets. (2) Run it as a saved version (\emph{Save \& Run All}). The notebook installs the pinned packages, builds the worlds and benchmark, runs the CPU experiments, the pilot, the planner, every LLM stage and the extension, and writes \code{outputs.zip}. Stage times in the reported run were: recall 183.4\,min, probes 19.3\,min, live sessions 76.2\,min, seed variance 27.2\,min, latency 15.5\,min, extension to levels 4 and 5 68.3 and 68.2\,min, second backbone 43.9\,min, independent families 18.1 and 17.5\,min, replay 13.4\,min, differential test 1.5\,min and crash trials 6.2\,min. (3) The outputs used in this paper come from the notebook as committed at \commit{3b4984ee3e963446d792124ffa337cb6a5b06e0a}, run from 2 to 3 November 2026, and are committed under \mdir{notebooks/outputs/} (plots, metrics, predictions, annotation sheets) together with \msrc{notebooks/outputs.zip}, which also holds the generated worlds, sessions, probes and logs. With the response caches attached and \code{CACHE\_ONLY=True}, the notebook regenerates every table without a GPU. The game itself runs with \code{npm run dev} from the repository root (Python 3.10+, Node 20.19+ or 22.12+, and a \code{GROQ\_API\_KEY}), and this paper builds with \code{npm run paper} from the repository root, which runs the bundled Tectonic and fails on any undefined reference, overfull box or bibliography warning.

\subsection{Corrections and audit of the runs}\label{sec:gaps}
The Review-02 run of this protocol found seven defects in the engine: (1) unbounded currency gains, (2) per-proposal instead of per-turn checking, (3) unchecked NPC drops and relocations, (4) a prompt that advertised a different trust range than the validator allowed, (5) secrets that never reached the model, (6) a load path that discarded the logged suffix, with the active NPC set outside the log, and (7) dialogue that described rejected changes. All seven are corrected in the evaluated code (\cref{M-sec:formal}) and covered by unit and property tests, including 3{,}000 random multi-proposal turns checked against an independent invariant checker. Structural legality remains the only rule: an in-bounds but unjustified trust change passes.

The corrected system was run five times. The first two runs (22 and 24 October 2026) revealed defects in how the notebook measured: buffered probes were scored as retrieval misses, the latency sessions were served from the cache, words from templates were mistaken for secret keywords, all stages drew from one random stream, the table of stages omitted the repair call, and a conservative planner kept both runs small. The third run (24 to 25 October) showed that these fixes worked, and an audit of its predictions then exposed defects in the benchmark itself. Some recall probes concerned an attribute that had been planted twice, the lenient rule accepted hedged and unparsed replies, each fact had only one distractor told to another NPC, B4 lacked its importance term, live sessions drifted from their scripts because the model made few moves, a violation was counted again on every later turn, intervals with no events collapsed to $[0,0]$, each attack category had three templates, and the oracle did not verify the NPC ids inside trust relationships. The fourth run (2 November) used the revised protocol but halted at its manifest cell. Its cell outputs showed four further problems: the B1 probe context repeated every F4 probe row, the planner overestimated the cost of live sessions and used 5 of the 11.25 available hours, the strict rule penalised replies that named both an old and a new value, and the two judges agreed poorly (Cohen's $\kappa=0.05$). Every finding led to a protocol amendment, recorded in the run manifest. The amendments introduced strict recall with lenient and adjudicated scores as secondary measures, knowledge updates and lure turns, the importance term in B4, ablation A8, a single probe context, six templates per attack category, lawfulness by intent together with the canonicaliser, the differential test, travel completed by the engine with violations counted once per turn, Clopper--Pearson intervals, the split of H1 into H1a and H1b, a cluster-robust linear model with a $t$ reference for H6, control items with an 80\% pass mark for the judges, a sample extended by measured time, and a new master seed so that no benchmark instance had been seen before. The fifth run, reported here, finished all stages with no recorded failure, and the one failed server launch, for the secondary backbone, recovered on its planned retry.

\subsection{Retrieval quality, recall by fact type, sensitivity and seed variance}\label{sec:retrieval-ext}

Scored on the 717 held-out probes older than the buffer, F4 placed the gold memory in its retrieved list for 99.6\% of them, as did A2, A4 and A8 (B2 100\%, B3 97.8\%, B5 95.5\%, B4 81.0\%, \cref{app:supp}). It ranked it slightly higher than B2 (MRR@6 0.805 against 0.786, not significant after correction) and clearly higher than the unscoped ablation A3 (0.742) and the scored memory stream B4 (0.346). It kept the paraphrased distractor out of 44.6\% of prompts, against 0.9\% for B2 and 6.5\% for A3. Removing the buffer (A2) kept it out of 90.6\%, because the distractor, told to a different NPC, then reaches the prompt only through retrieval. Disabling the fallback (A4) raised MRR@6 to 0.815, since the fallback replaces a short scoped list with unscoped neighbours.

Recall depends on the kind of fact (\cref{tab:facttype}, values in \osrc{metrics/recall_by_fact_type.csv}). There, the outdated column counts replies that gave the value from before a knowledge update, the lenient column accepts the gold value even when a competing value is also named, and the adjudicated column lets Qwen2.5-7B decide the hedged replies. On plain facts at $a\ge20$, F4 recalled 79.1\% and B2 87.4\%. Knowledge updates were hard for every memory (F4 20.7\%, best B0 and B4 at 25.7\%), and the superseded value came up most often with full history (15.0\%). Under the lenient rule F4 recalled 83.1\%, and when the Qwen2.5-7B adjudicator decided the 19.2\% of F4 replies that named two values, 74.3\%. B2 stayed ahead under both rules (86.0\% and 80.6\%), and the adjudicated non-inferiority test also failed (lower bound $-9.8$ points). The exploratory tests (Holm-corrected within their family) were: F4 against B2 $-5.6$ points ($p=0.044$), against B4 $+9.5$ ($p=0.0011$), against B5 $+3.0$, F4v1 $+0.4$, A3 $+0.6$ and A8 $+1.9$, and A8 against F4v1 $-1.5$ (all $p=1.0$). The budget and the prompt change between F4v1 and F4 therefore have no measurable effect on recall at $a\ge20$.

\subsection{Validator differential test and grounding}\label{sec:differential}

On the probes of \cref{M-tab:probes}, direct writes most often broke O1 in theft attacks (14 times), O7 (10) and O8 (9) in currency attacks, and O1 (5) and O3 (3) in teleportation attacks. Parse success was 94.0\%, and secret leaks over all attacks, \ci{1.0}{0.5}{1.7}\%, are an upper bound because the leak scorer matches keywords. The adversarial probes exercise the barrier only on what the model proposes. The differential test exercises it directly. For each world it builds 40 random valid states and plays 60 random turns in each, every turn carrying one to three proposals drawn from all event types, including engine-only and unknown ones. References may be canonical, adjacent, distant, display names, invented ids or of the wrong type, and amounts are random. The oracle labels every proposal on its own transition and audits every whole turn after commit. \Cref{tab:differential} reports the result for all seven worlds (\osrc{metrics/table5c_validator_differential.csv}) as rates in \% with exact binomial 95\% intervals and counts in parentheses, where the columns by intent count display names and slugs as references to the entity. For the zero counts, the upper 95\% bound is 0.01\% over all unlawful proposals and at most 0.39\% for any single type. The corrected barrier accepted none of 26{,}273 unlawful proposals and committed no violating turn among 16{,}800. It rejected 6 of 7{,}382 lawful proposals. All six were NPC takes of an object in the player's inventory, which the oracle permits and the validator forbids. The Review-02 validator accepted 51.7\% of unlawful proposals, including every engine-only event, 57.0\% of unlawful currency changes and 45.8\% of unlawful NPC drops, and 1{,}485 of its turns violated an invariant. Judged by intent, the corrected barrier rejected 9.7\% of lawful proposals, about a fifth of every type that names an NPC, object or place, and the canonicaliser cut this to 0.10\% with no validator gap.

\subsection{Replay and recovery}\label{sec:replay}

Replay behaved as \cref{M-prop:replay} predicts. \Cref{tab:replay} covers 42 CPU sessions of 200 turns (six per world, 371.5 events on average) committed through the real event store and reducer, together with 300 randomised crash trials. Every event-sourced live session and every CPU replay session was rebuilt exactly, whether by a full fold, from a snapshot and its suffix, or after a restart. \Cref{fig:replay} plots the median rebuild time at each snapshot point on a log scale over the 42 sessions, comparing a full replay of the event log (A7) with snapshot loading. Full replay slowed as the log grew, to a median of 244.2\,ms at turn 160, whereas loading a snapshot took between 1.1 and 1.5\,ms throughout. The plot's title strip, which repeats the consistency rates of \cref{tab:replay}, is cropped. Every simulated crash was recovered by the corrected load path. The Review-02 path, which ignores the suffix, recovered none of the crashes of the replay sessions and lost 8 turns on average. In the 300 randomised crash trials, the corrected path stayed consistent every time, whereas the Review-02 path did so in 93 trials (31.0\%) and lost 5.9 turns on average. Its consistent trials were the 63 in which the crash followed a snapshot write directly and the 30 in which no committed turn was lost, for example a crash before the first snapshot.

\subsection{Latency and token cost}\label{sec:latency}

Local work was negligible against generation (per-stage values in \cref{app:supp}): 15.0\,ms at P50 and 22.4\,ms at P95 for the live F4 graph run single-stream. The validator needed 0.013\,ms at the median and 0.96\,ms at P95, well within the 5\,ms limit set by H4, and most local time went to the commit node (SQLite append, reduction and indexing, 8.9\,ms). The LLM call took 7{,}410\,ms at P50 and 14{,}893\,ms at P95 per live turn, and 6{,}750\,ms and 7{,}847\,ms per recall request. Dialogue repair adds a second LLM call on turns with a rejected proposal (5.8 to 7.9\,s on the 3 of 24 single-stream turns that needed it), which is why end-to-end P95 reached 15.0\,s. In the batched live stage, an F4 turn waited a median of 54.8\,s for the LLM, which reflects a setting tuned for throughput rather than interaction. Per 100 turns F4 consumed 146{,}765 input and 14{,}456 output tokens, against 443{,}762 and 12{,}562 for full history (\cref{app:supp}). Because the models were self-hosted, no monetary cost is reported.

\emph{Memory is necessary in both.} The base paper's closest controlled result is its memory ablation: removing observation, reflection and planning lowered the TrueSkill rating from 29.89 to 21.21, eight standard deviations. Removing long-term memory here (A1) lowered recall of facts 20 or more turns old from 63.7\% to 0.0\%. Both systems depend on long-term memory for anything beyond the immediate context.

\emph{The base paper's retrieval rule forgets under a budget.} B4 ranks memories with the base paper's recency, importance and relevance terms, and the primary model assigned each memory its importance a single time (3{,}890 ratings with a mean of 3.78 on the 1 to 10 scale). Under the shared budget, B4 recalled 54.2\% at $a\ge20$, against 63.7\% for F4 ($p_{\text{Holm}}=0.0011$), and its recall dropped to 33.3\% at age 80 and 15.0\% at age 160 as recency decay crowded old memories out of the budget. Relevance alone (B2) was stronger than both: it recalled 69.3\%, more than F4 ($p_{\text{Holm}}=0.044$), and F4's better ranking (MRR@6 0.805 against 0.786) and distractor exclusion (44.6\% against 0.9\% of prompts) did not turn into recall. Unlike the base paper, the engine spends no LLM call on writing a memory.

\emph{State control has no counterpart in the base paper.} Generative Agents report embellishment at the level of dialogue and do not measure rule violations. With the corrected barrier in place, none of the probe or live outputs of the four models led to a committed state violation (\cref{M-tab:probes,tab:perworld}), and the event log rebuilt the live state exactly. The closest reported measurement is NCP-Bench \cite{ma2026ncp}, where the best model kept its narrative commitments in only 42\% of runs after 20 turns when checked afterwards by LLM auditors. Here the specification is enforced before commit, which protects the state, but the dialogue still contradicted rejected changes on 3.6\% of non-move live F4 turns by the cue proxy, and dialogue repair did not close that gap on the turns it rewrote.

\subsection{Error analysis}\label{sec:errors}

Automatic coding locates the failures (counts per condition in \cref{app:supp}). Retrieval caused none of F4's recall failures, since it never missed. Instead, 257 replies gave the gold value together with a rival value, 132 disregarded a retrieved gold turn, 38 gave the distractor's value and 14 a superseded value. Rolling contexts failed by forgetting (546 misses for B1), generic RAG by hedging, ignoring and confusing retrieved chunks (324, 199 and 103), the scored memory stream B4 partly by forgetting (86 misses), and the ablation without long-term memory by both (638 misses, 213 confusions). The desynchronisation proxy flagged 16 F4 turns against 18 for F4v1, 13 for F2 and 12 for A6, the conditions that can reject proposals. In conditions that never reject, only the arrival cue can fire: 4 turns each for F1 and F3 and 2 for A5.

\subsection{Failure modes, trust boundary and audit coverage}\label{sec:failures}

\Cref{tab:failures} gathers every failure mode that the run measured, or that lies outside what it measured, with the component it arises in, the evidence and its status.
