\section{Algorithms}\label{sec:algorithms-ext}

\Cref{alg:turn} is one turn of the engine, following nodes 1 to 9 of \cref{M-fig:arch}: input sanitisation, scoped retrieval, budgeted prompt assembly, generation and parsing, validation against a running state, repair of a reply whose proposals were rejected, and the commit that appends events, reduces the state, updates both memory tiers and writes periodic snapshots.

\begin{algorithm}[H]
\caption{One turn of the engine (nodes 1 to 9 of \cref{M-fig:arch})}\label{alg:turn}
\begin{algorithmic}[1]
\Require player input $u$, active NPC $n$, state $S_t$, store $M$, buffer $H$, log $\mathcal{E}$
\State $u\gets$ \Call{Trim}{$u$}, \textbf{if} $u=\varepsilon$ \textbf{then} $u\gets$ ``(silence)''
\State $\mathbf{q}\gets$ \Call{Embed}{$u$},\quad $\mathcal{R}\gets$ \Call{ScopedRetrieve}{$\mathbf{q},\pi(S_t),n$} \Comment{\cref{alg:retrieve}}
\State $(\mathcal{R}',h)\gets$ \Call{PackContext}{$\mathcal{R},H$, 1{,}600 chars},\quad $x\gets$ \Call{BuildPrompt}{$S_t,n,u,\mathcal{R}',h$}
\State $y\gets$ \Call{LLM}{$x$}, \quad $o\gets$ \Call{ParseJSON}{$y$} \Comment{on failure: $y$ becomes dialogue, no proposals}
\State $\hat S\gets S_t$,\quad $E_t\gets[\,]$,\quad $\mathit{rej}\gets[\,]$
\For{$(\tau,p)\in o.\mathrm{proposals}$}
  \If{$V(\tau,p,\hat S,S_t)$} $E_t.\mathrm{append}(e(\tau,p))$,\ $\hat S\gets\delta(\hat S,e(\tau,p))$ \Else\ $\mathit{rej}.\mathrm{append}((\tau,p))$ \EndIf
\EndFor
\If{$\mathit{rej}\neq[\,]$} $o.\mathrm{dialogue}\gets$ \Call{Repair}{$o,E_t,\mathit{rej}$} \Comment{one LLM call, neutral narration on failure}
\EndIf
\State append $e_{\text{speech}}$ and $E_t$ to $\mathcal{E}$ in one transaction, \quad $S_{t+1}\gets\foldl(\delta,S_t,E_t)$
\State $H.\mathrm{push}(u,o.\mathrm{dialogue},n)$,\quad $M.\mathrm{add}(\mathbf{q},\ o.\mathrm{summary},\ t{+}1,\ \pi(S_{t+1}),\ n)$
\If{$|M|>1000$} keep the newest 500 entries of $M$ \EndIf
\If{$(t+1)\bmod 16=0$} write snapshot $(S_{t+1},\max\mathrm{id}(\mathcal{E}))$ atomically and save $M$ \EndIf
\State \Return dialogue, narration, $S_{t+1}$
\end{algorithmic}
\end{algorithm}

\Cref{alg:retrieve} is the retrieval step, \eqref{M-eq:retrieve} as code: it over-fetches $fk$ nearest neighbours by exact inner product, keeps those inside the current scope, and falls back to the unscoped list when fewer than $\theta$ survive.

\begin{algorithm}[H]
\caption{\textsc{ScopedRetrieve}\newline(\code{make\_node\_retrieval}, \code{FAISSMemory.search})}\label{alg:retrieve}
\begin{algorithmic}[1]
\Require query $\mathbf{q}$, location $\ell$, NPC $n$, $k=6$, $f=5$, $\theta=3$
\State $C\gets$ exact inner-product top-$\min(fk,|M|)$ of $\mathbf{q}$ over $M$
\State $R\gets[\,]$
\For{$m\in C$ in descending similarity}
  \If{$\phi_{\ell,n}(m)$} append $m$ to $R$, \textbf{if} $|R|=k$ \textbf{then break} \EndIf
\EndFor
\If{$|R|<\theta$} $R\gets$ first $k$ entries of $C$ \Comment{relaxation fallback, unscoped}
\EndIf
\State \Return $R$
\end{algorithmic}
\end{algorithm}


\subsection{Paired five-way commit and audit}\label{sec:alg-protocol}
\Cref{alg:protocol} is the core of the evaluation protocol of \cref{M-sec:protocol}. One model output per probe is committed through the corrected barrier, the corrected barrier behind a canonicaliser, the Review-02 barrier, the reducer alone and by direct writes, and each post-state is audited by the oracle.

\begin{algorithm}[H]
\caption{Paired five-way commit and independent audit of one probe output}\label{alg:protocol}
\begin{algorithmic}[1]
\Require scenario state $S$, prompt $x$, seed $s=h(\text{probe id})$ \Comment{independent of condition}
\State $y\gets$ \Call{LLM}{$x$, seed $s$}, \quad $o\gets$ \Call{ParseJSON}{$y$}
\For{mode $\in\{\text{barrier},\ \text{barrier canon},\ \text{barrier v1},\ \text{reducer},\ \text{direct}\}$}
  \If{mode $=$ barrier} $S'\gets\foldl(\delta,S,E)$ with $E$ from the running-state check of \cref{M-eq:commit}
  \ElsIf{mode $=$ barrier canon} as barrier, after mapping exact display names and slugs to ids \Comment{offline candidate}
  \ElsIf{mode $=$ barrier v1} $S'\gets\foldl(\delta,S,[e(\tau,p):V_{\text{v1}}(\tau,p,S)])$ \Comment{Review-02 validator}
  \ElsIf{mode $=$ reducer} $S'\gets\foldl(\delta,S,[e(\tau,p): \tau\ \text{a known type}])$ \Comment{ablation A5}
  \Else\ $S'\gets$ write each proposal and each new entity into a copy of $S$ \Comment{no clamping}
  \EndIf
  \State $v_{\text{mode}}\gets$ \Call{Oracle}{$S,S'$, committed list} \Comment{O1 to O8, no validator code}
\EndFor
\State \Return the five verdicts and lawful/unlawful counts per proposal, as written and by intent
\end{algorithmic}
\end{algorithm}

\subsection{Complexity}
With $|M|\le 1000$ entries, $d=384$ and $p$ proposals per turn: exact search is $O(|M|d)$. Validation is $O(p)$ lookups plus one reduction per accepted proposal for the running state. Reduction is $O(p\,|S|)$ because each event deep-copies the state. Recovery from the latest snapshot is $O(|S|+r)$ with $r$ the events since it. Measured costs are in \cref{sec:latency}.

\section{Dataset Description and Usage}\label{sec:dataset-ext}

The dataset is a benchmark built for this study: seven worlds, teacher-forced recall sessions, adversarial probes with lawful twins, and live-session scripts, generated deterministically by the evaluation notebook from a master seed, together with the model outputs and metrics of the reported run. \Cref{sec:data-files} lists the released files and how each is used.

\subsection{World suite}
A single hand-made world cannot support generalisation claims, and a benchmark written by the system's authors risks being tuned to it. The suite therefore has four families (\cref{tab:worlds,fig:worlds}): W1, the in-house dark-fantasy development world (\esrc{Backend/game/world_seed.json}), and W2a to W2c, converted by a deterministic seeded script from the crowd-written \href{https://dl.fbaipublicfiles.com/parlai/light/light-environment.pkl}{LIGHT environment file} \cite{urbanek2019light} (CC BY-NC 4.0), with LIGHT's fragmented room graph joined by a seeded spanning tree and two templated secrets per NPC built from words that occur nowhere else in the world. W3 is a 24-location science-fiction station authored in the notebook from a written specification before any system run, and W4-32 and W4-128 are procedural graphs (random spanning tree plus about 30\% extra edges) with templated names. No system setting was tuned on W2 to W4. W3 is held out from tuning but was \emph{not} independently authored.

\subsection{Teacher-forced long-horizon recall sessions}\label{sec:recall-sessions}
A session is a fixed script of $H\in\{50,100,200\}$ player turns. For each fact age $a\in\{5,10,20,40,80,160\}$ with $a<H-1$, two facts are \emph{planted} with a randomly chosen NPC and \emph{probed} $a$ turns later with the same NPC, using 15 attribute templates (meeting place, password, debt, and so on), each attribute at most once per session. Each fact has a paraphrased \emph{distractor} with a different value told to a different NPC, placed between plant and probe where possible. A quarter of facts are \emph{knowledge updates}: the player first tells one value and corrects it at the gold turn. Half have a \emph{lure turn}, small talk about the same topic. Values come from pools of invented or uncommon words, and any value whose key word occurs anywhere in a world's text is removed, so a correct answer cannot come from lore. A probe is correct (strict) when the output parses and the reply names the gold key word as a whole word and names neither the distractor's value nor the outdated one, \emph{confused} when it names the distractor's value instead, and \emph{hedged} when it names the gold value and a competing one.

Fillers are small talk with the NPC of the next scripted event, with varied scripted replies, and the player stands at that NPC's location. NPC replies and memory summaries in the history are scripted (teacher forcing), so every condition sees the same history and the LLM is called only at probe turns. The full pool holds 210 sessions with 2{,}092 facts (23.7\% knowledge updates, 48.4\% with a lure turn). With five sessions per world and horizon, each condition answers 1{,}045 probes over 105 sessions: 897 on held-out worlds, of which 537 have $a\ge20$. Because a fact is always probed with the NPC it was told to, at that NPC's fixed location, this design favours scoping. Knowledge updates and lure turns are the only probes where scoping cannot separate the gold memory from its competitors.

\subsection{Adversarial invariant probes with lawful twins}
Each probe is a scenario (a world state with the player beside an NPC, three teacher-forced history turns, and one attack turn) in one of seven categories, each paired with a lawful twin: teleportation (twin: walk to an adjacent location), item fabrication (pick up a present item), theft or duplication (pick up a present item), trust inflation (thank the NPC), currency exploits (pay a small affordable amount), prompt injection \cite{greshake2023indirect} (an ordinary question), and secret extraction at trust 0 (the same request at trust 80). Each category has six attack templates. The run used 22 attacks per category per world, 1{,}078 in all, with 1{,}027 twins: theft has twins for 103 of its 154 attacks. A probe prompt is the same under every memory condition, so every attack and twin was posed once, under F4's context, giving 2{,}105 probe outputs.

\subsection{Live sessions}
Live sessions run the backend's real LangGraph nodes every turn, so the model's own replies and committed state feed later turns. Each script has 39 turns: four plants with two NPCs, walks between them (one ``I walk over to \ldots'' turn per edge), small talk, two lawful trades, six attacks, and four late probes at fact ages of about 20 to 32 turns. Two scripts per world give 14 sessions per condition, paired on identical inputs. When the model does not commit a scripted move, the engine completes it, so all conditions follow one trajectory, and model move compliance is reported separately.

\subsection{Sources, format and release}\label{sec:data-files}
\emph{Sources.} W1 is the game's own seed (\esrc{Backend/game/world_seed.json}). W2a to W2c are converted from the LIGHT environment file \cite{urbanek2019light} (\code{light-environment.pkl}, CC BY-NC 4.0), whose rooms (setting and description), characters with personas, and objects become locations, NPCs and objects. W3 and W4 are generated in the notebook. \emph{Format.} Each world is a JSON document in the game's save schema: metadata, locations with \code{connected\_to} lists, NPCs with description, personality, knowledge, secrets and an \code{alive} flag, objects with location and owner, world rules, the player (location, inventory, currency), trust relationships, journal and turn. Recall sessions (session id, world, horizon, scripted turns, planted facts), adversarial probes (category, attack, lawful twin, scenario state, history) and live scripts are JSON Lines files with one record per line. \emph{Size.} The notebook generates the full pools of the largest sample-size level, 210 recall sessions, 1{,}960 probe scenarios and 35 live scripts (about 8\,MB, 87\,MB and 0.2\,MB), and a run uses a prefix of each. \emph{Release.} The generated data, every prediction and metric file, and the blinded annotation sheets are committed under \mdir{notebooks/outputs/} and in \msrc{notebooks/outputs.zip}. The W2 worlds inherit LIGHT's non-commercial licence.

\subsection{How the data is used}
Recall sessions answer RQ1: every memory condition replays the same teacher-forced history and is asked the same probes, so recall, MRR and gold-in-prompt rates are paired across conditions. Probes answer RQ2: each attack and its lawful twin is committed five ways (\cref{M-sec:protocol}), and the differential test (\cref{sec:differential}) adds random proposals. The paired before-and-after comparison uses all three kinds of data. Live sessions answer RQ3 and RQ4: they run the real backend graph each turn for the $2\times2$ factorial and the control ablations and record latency and tokens. RQ5 uses the split by world family (W1 is in-distribution, W2 to W4 are held out from tuning) and three further models on a subset: a smaller model of the same family and two models of other families. Every table in \cref{M-sec:results} can be regenerated from the prediction files and response caches without a GPU (\cref{sec:repro}).

\section{Implementation and Run}\label{sec:impl-ext}

\subsection{Software stack}
The engine has four tiers. The presentation tier (React, TypeScript, Zustand) streams turns over a WebSocket. The orchestration tier (FastAPI with per-session async locks) runs a compiled nine-node LangGraph \code{StateGraph} (\bsrc{graph/definition.py}). The validation tier is the barrier (\bsrc{game/validator.py}). The storage tier holds the SQLite event log and snapshots (\bsrc{core/event_store.py}, \bsrc{core/snapshot.py}, \bsrc{core/recovery.py}), the FAISS store with all-MiniLM-L12-v2 embeddings (\bsrc{memory/faiss_index.py}) and the turn buffer (\bsrc{memory/short_term.py}). In the shipped game the LLM is a hosted endpoint (Groq, \code{openai/gpt-oss-120b}, temperature 0.35, \esrc{Backend/config.py}). In the evaluation it is a self-hosted model served by vLLM \cite{kwon2023vllm}.

\subsection{System under test}\label{sec:repro}
The notebook \msrc{notebooks/npc-memory-state-benchmark.ipynb} does not clone the repository: it embeds the backend source of commit \commit{9b38dcfeb506b797c38a07a8bc357da707e34e7c} as a hashed bundle (SHA-256 \code{84a4c1ced397}\ldots, 45 files), together with the validator and prompt builder of the Review-02 commit \commit{0ea345fe140b359d7e82e77ffb2fdfa74caf0e7c} for condition F4v1, asserts the hash, and imports the real backend modules (reducer, validator, event store, snapshots, recovery, prompt builder and packing, FAISS memory, buffer, JSON extractor and the LangGraph node factories). Live conditions are built from the backend's own nodes, swapping only the nodes a condition changes. Only the baselines, the oracle and the benchmark generators are new code. Before any GPU time, a self-test with a deterministic mock LLM checks that the oracle flags direct writes, that the corrected barrier commits no more violations than the Review-02 barrier, that event-sourced sessions replay exactly, that the corrected load path recovers after a crash, and that the notebook's scoped retrieval matches \code{node\_retrieval}. \Cref{tab:config} lists the run configuration.

\subsection{Sample-size planning}
Twelve pre-declared levels (index 0 to 11, \cref{app:ladder}) fix sessions per world and horizon, probes per category and world, and live sessions per world, raising one costly dimension at a time, so a smaller level is a prefix of a larger one. A pilot of 256 jobs measured steady-state throughput, and a planner chose the largest level whose estimated cost fitted the time left after reserves for the analysis, the latency benchmark, the second backbone and the independent families: level 3 (7.28\,h estimated of 7.69\,h available). After the required stages, seed variance and the latency benchmark, the run extended the sample one level at a time from its own measured rates, using elapsed time only: level 4 took 68.3 minutes against 90.9 projected, and level 5 68.2 against 90.4. It stopped at level 5 because level 6 needed about 46 minutes and 26 were left before the reserves. The run ended after 9.66 of the 11.25 budgeted hours. Coverage was complete: 13{,}585 recall, 2{,}105 probe, 3{,}822 live-turn, 1{,}656 seed-variance, 117 repair, 329 judge, 1{,}258 adjudication and 96 single-stream latency rows, 960 and 770 for the second backbone, and 840 and 770 for each independent family, none lost to a deadline. The primary server generated 24{,}216 responses and served 1{,}530 from the response cache (pilot responses reused by the main stages, and identical prompts shared by conditions). \Cref{fig:gpu} shows the run profile.

\subsection{Execution procedure}
(1) Create a Kaggle notebook from \msrc{notebooks/npc-memory-state-benchmark.ipynb}, select \emph{GPU T4 x2}, enable Internet, and optionally attach an independently written \code{w3\_world\_seed.json} or completed rating sheets. (2) Run it as a saved version (\emph{Save \& Run All}). The notebook installs the pinned packages, builds the worlds and benchmark, runs the CPU experiments, the pilot, the planner, every LLM stage and the extension, and writes \code{outputs.zip}. Stage times in the reported run were: recall 183.4\,min, probes 19.3\,min, live sessions 76.2\,min, seed variance 27.2\,min, latency 15.5\,min, extension to levels 4 and 5 68.3 and 68.2\,min, second backbone 43.9\,min, independent families 18.1 and 17.5\,min, replay 13.4\,min, crash trials 6.2\,min, differential test 1.5\,min. (3) The outputs used in this paper come from the notebook as committed at \commit{3b4984ee3e963446d792124ffa337cb6a5b06e0a}, run from 2 to 3 November 2026, and are committed under \mdir{notebooks/outputs/} (plots, metrics, predictions, annotation sheets) together with \msrc{notebooks/outputs.zip}, which also holds the generated worlds, sessions, probes and logs. With the response caches attached and \code{CACHE\_ONLY=True}, the notebook regenerates every table without a GPU. The game itself runs with \code{npm run dev} from the repository root (Python 3.10+, Node 20.19+ or 22.12+, and a \code{GROQ\_API\_KEY}), and this paper builds with \code{npm run paper} from the repository root, which runs the bundled Tectonic and fails on any undefined reference, overfull box or bibliography warning.

\subsection{Corrections and audit of the runs}\label{sec:gaps}
The Review-02 run of this protocol found seven defects in the engine: (1) unbounded currency gains, (2) per-proposal instead of per-turn checking, (3) unchecked NPC drops and relocations, (4) a prompt that advertised a different trust range than the validator allowed, (5) secrets that never reached the model, (6) a load path that discarded the logged suffix, with the active NPC set outside the log, and (7) dialogue that described rejected changes. All seven are corrected in the evaluated code (\cref{M-sec:formal}) and covered by unit and property tests, including 3{,}000 random multi-proposal turns checked against an independent invariant checker. Structural legality remains the only rule: an in-bounds but unjustified trust change passes.

The corrected system was run five times. The first two runs (22 and 24 October 2026) exposed measurement defects in the notebook: retrieval metrics that counted buffered probes as misses, latency sessions answered from the cache, template words taken as secret keywords, a shared random stream, a stage table without the repair call, and a planner safety factor that kept both runs small. The third run (24 to 25 October) confirmed those fixes, but an audit of its predictions found defects in the benchmark itself: recall probes about an attribute planted twice, lenient scoring that counted hedged and unparsed replies as correct, one cross-NPC distractor per fact, a B4 without the importance term, live sessions that left their script because the model committed few moves, violations counted again on every later turn, zero-event intervals of $[0,0]$, three templates per attack category, and an oracle that did not check NPC ids in trust relationships. The fourth run (2 November) executed the revised protocol but stopped in its manifest cell, and its cell outputs showed that the B1 probe context duplicated every F4 probe row, that the planner overestimated live cost and used only 5 of 11.25 hours, that strict scoring penalised replies naming an old and a new value, and that the two judges disagreed (Cohen's $\kappa=0.05$). Each finding changed the protocol, as listed in the manifest's protocol amendments: strict recall with lenient and adjudicated secondary scores, knowledge updates and lure turns, B4 with importance, ablation A8, one probe context, six templates per category, intent-level lawfulness and the canonicaliser, the differential test, engine-completed travel with new violations per turn, Clopper--Pearson intervals, H1a and H1b, a cluster-robust linear model for H6 with a $t$ reference, judge control items with an 80\% threshold, a time-based extension of the sample, and a fresh master seed so that no benchmark instance had been inspected. The fifth run is the one reported here. It completed every stage without a recorded failure, and the secondary backbone's first server launch failed and recovered on the planned retry.

\subsection{Retrieval quality, recall by fact type, sensitivity and seed variance}\label{sec:retrieval-ext}

Scored on the 717 held-out probes older than the buffer, F4 placed the gold memory in its retrieved list for 99.6\% of them, as did A2, A4 and A8 (B2 100\%, B3 97.8\%, B5 95.5\%, B4 81.0\%, \cref{app:supp}). It ranked it slightly higher than B2 (MRR@6 0.805 against 0.786, not significant after correction) and clearly higher than the unscoped ablation A3 (0.742) and the scored memory stream B4 (0.346). It kept the paraphrased distractor out of 44.6\% of prompts, against 0.9\% for B2 and 6.5\% for A3. Removing the buffer (A2) kept it out of 90.6\%, because the distractor, told to a different NPC, then reaches the prompt only through retrieval. Disabling the fallback (A4) raised MRR@6 to 0.815, since the fallback replaces a short scoped list with unscoped neighbours.

Recall depends on the kind of fact (\cref{tab:facttype}). On plain facts at $a\ge20$, F4 recalled 79.1\% and B2 87.4\%. Knowledge updates were hard for every memory (F4 20.7\%, best B0 and B4 at 25.7\%), and full history gave the outdated value most often (15.0\%). \subsection{Validator differential test and grounding}\label{sec:differential}

The adversarial probes exercise the barrier only on what the model proposes. The differential test drives it directly: in 40 random valid states per world, each with 60 random turns of one to three proposals of every event type (engine-only and unknown types included), with references that are canonical, adjacent, distant, display names, invented ids or the wrong type, and with random amounts. The oracle labels each proposal on its own transition, and each turn is also audited whole after commit (\cref{tab:differential}). The corrected barrier accepted none of 26{,}273 unlawful proposals and committed no violating turn among 16{,}800. It rejected 6 of 7{,}382 lawful proposals, all NPC takes of an object the player carries, which the oracle allows and the validator does not. The Review-02 validator accepted 51.7\% of unlawful proposals, including every engine-only event, 57.0\% of unlawful currency changes and 45.8\% of unlawful NPC drops, and 1{,}485 of its turns violated an invariant. Judged by intent, the corrected barrier rejected 9.7\% of lawful proposals, about a fifth of every type that names an NPC, object or place, and the canonicaliser cut this to 0.10\% with no validator gap.

\subsection{Latency and token cost}\label{sec:latency}

Local work was negligible against generation (per-stage values in \cref{app:supp}): 15.0\,ms at P50 and 22.4\,ms at P95 for the live F4 graph run single-stream. Validation took 0.013\,ms at P50 and 0.96\,ms at P95, inside the 5\,ms bound of H4, and the commit node (SQLite append, reduction, indexing) dominated local time at 8.9\,ms. The LLM call took 7{,}410\,ms at P50 and 14{,}893\,ms at P95 per live turn, and 6{,}750\,ms and 7{,}847\,ms per recall request. Dialogue repair adds a second LLM call on turns with a rejected proposal (5.8 to 7.9\,s on the 3 of 24 single-stream turns that needed it), which is why end-to-end P95 reached 15.0\,s. Under the batched live stage the median LLM time per F4 turn was 54.8\,s, a throughput setting rather than an interactive one. Per 100 turns F4 consumed 146{,}765 input and 14{,}456 output tokens, against 443{,}762 and 12{,}562 for full history (\cref{app:supp}). Because the models were self-hosted, no monetary cost is reported.

\subsection{Generalisation across worlds and models}\label{sec:general-ext}

By family, F4 minus B1 recall at $a\ge20$ was $+0.636$ (W2), $+0.689$ (W3) and $+0.612$ (W4), and direct-minus-barrier attack success $+0.032$, $+0.019$ and $+0.016$, so both H7 directions hold. F4 did not beat the best baseline on every world: it was ahead of B2 on W1 and W4-32, level on W3, and behind on W2a to W2c and W4-128, where it recalled 48.9\% against 62.5\%. \emph{Memory is necessary in both.} The base paper's closest controlled result is its memory ablation: removing observation, reflection and planning lowered the TrueSkill rating from 29.89 to 21.21, eight standard deviations. Removing long-term memory here (A1) lowered recall of facts 20 or more turns old from 63.7\% to 0.0\%. Both systems depend on long-term memory for anything beyond the immediate context.

\emph{The base paper's retrieval rule forgets under a budget.} B4 ranks memories by the base paper's recency, importance and relevance terms, with importance rated once per memory by the primary model (3{,}890 ratings, mean 3.78 on the 1 to 10 scale). At the same budget its recall at $a\ge20$ was 54.2\%, against 63.7\% for F4 ($p_{\text{Holm}}=0.0011$), and fell to 33.3\% at age 80 and 15.0\% at age 160, because recency decay pushes old memories out of the budget. Relevance alone (B2) was stronger than both: it recalled 69.3\%, more than F4 ($p_{\text{Holm}}=0.044$), and F4's better ranking (MRR@6 0.805 against 0.786) and distractor exclusion (44.6\% against 0.9\% of prompts) did not turn into recall. Unlike the base paper, the engine spends no LLM call on writing a memory.

\emph{State control has no counterpart in the base paper.} Generative Agents report embellishment at the level of dialogue and do not measure rule violations. In the engine no probe or live output committed a state violation through the corrected barrier, for any of four models (\cref{M-tab:probes,tab:perworld}), and the event log reproduced the live state exactly. The closest reported measurement is NCP-Bench \cite{ma2026ncp}, where the best model kept its narrative commitments in only 42\% of runs after 20 turns when checked afterwards by LLM auditors. Here the specification is enforced before commit, which protects the state, but the dialogue still contradicted rejected changes on 3.6\% of non-move live F4 turns by the cue proxy, and dialogue repair did not close that gap on the turns it rewrote.

\subsection{Error analysis}\label{sec:errors}

Automatic coding locates the failures (counts per condition in \cref{app:supp}). None of F4's recall failures came from retrieval: it had no retrieval miss, 257 replies named the gold value and a competing one, 132 ignored a retrieved gold turn, 38 used the distractor's value and 14 the outdated one. Rolling contexts failed by forgetting (546 misses for B1), generic RAG by hedging, ignoring and confusing retrieved chunks (324, 199 and 103), the scored memory stream B4 partly by forgetting (86 misses), and the ablation without long-term memory by both (638 misses, 213 confusions). The desynchronisation proxy flagged 16 F4 turns against 18 for F4v1, 13 for F2 and 12 for A6, the conditions that can reject proposals. In conditions that never reject, only the arrival cue can fire: 4 turns each for F1 and F3 and 2 for A5.

\subsection{Failure modes, trust boundary and audit coverage}\label{sec:failures}

\Cref{tab:failures} gathers every failure mode that the run measured, or that lies outside what it measured, with the component it arises in and its status. Two failure modes found in earlier versions, the load path that discarded logged turns and the missing currency rule, are fixed and confirmed by R2 and R1 (\cref{M-tab:before-after}). State control fails at its two edges, the input (display names instead of ids) and the output (narration and dialogue, which no state check reads).
